# Few-shot agent distillation：端到端框架 v0（先整体跑通）

日期：2026-11-02 CST（第 2 版，13:10 CST）。状态：方向已经用户确认，预注册前不使用 GPU，也不调用 teacher。
依据：
- 用户 11-02 12:50–13:04 CST 的意见；
- 用户 10-26 的 pipeline v0.1（docs/direction/2026-10-26_agent_distillation_pipeline_v0_1_ZH.md）。

## 0. 原则（用户确认）

1. **先整体跑通，再逐个改部件。** v0 里每个部件只用最简单、能跑的实现。第一轮结束就在 dev140 上与 baseline 比较。之后每次只替换一个部件，再看整体结果。
2. **训练数据只有 K 条成功轨迹，与 baseline 相同。** 额外监督只能来自 teacher 和 harness 的查询，或合成数据。不使用其他官方训练任务，所以 V2 的 200 任务池不再用于主方法。dev140 只做最终测评。
3. **评价对象是学生的整条回答。** Harness 与 teacher 一起评价学生的完整轨迹，理解学生的计划。和 teacher 不同但能完成任务的选择不算错（殊途同归），只在计划真正走不通的地方做最小修改。
4. **few-shot 的核心问题是监督太少。** Harness 和 teacher 围绕学生的错误合成更多练习，学生多次作答，从中找到最一致的错误模式，集中在这些模式上学习。
5. **快，先关注机制能否跑通。** 省掉 v0.1 的严格项：
   - 人工逐条检查理由标签（保留自动检查）；
   - 逐块撤销的最小性检验（只记录修改距离）；
   - 第一轮的条件翻转练习。

撤回：部件 A 的"最早关键事件截前缀"，V2b-mix 和 V2b-search。

## 1. 整体流程（一轮）

起点：K 条 teacher 成功示范，SFT 得到 θ₀（K = 10/20/30，先做 K20；θ₀ 是主网格 K20 轨迹 SFT 的 seed 0，dev140 上 78/140）。

θ₀ 在自己的 K20 任务上 80/80 全部成功（1 次 greedy 加 3 次采样）。原题上几乎没有错误可修，所以**错误必须由 harness 合成的练习暴露出来**。合成练习是整个框架的入口。

| 步骤 | 做什么 | 输出 |
|---|---|---|
| S 合成练习 | harness 从 K 个任务自己的游戏出发合成新任务和出错状态（§2.S），每个合成任务必须可执行、有成功见证、与 dev140 不重合 | 合成任务池 |
| A 学生作答 | θ_r 在合成任务上独立执行（1 次 greedy 加 3 次采样） | 学生轨迹，含成功和失败 |
| B 整体评价与最小修改 | harness 逐步标注执行事实；teacher 读完整轨迹，判断计划、可保留的选择和走不通的位置，提出最小修改；harness 闭环执行验证 | 验证成功的修复 episode 和评价记录 |
| C 错题集扩展 | 按 D 的结果，针对一致的错误模式合成更多同类任务，学生作答，失败的走 B | 更多修复，以及学生自己的成功 |
| D 梯度分析（两个 variant） | 在 θ_r 上计算每个修复 episode 的梯度 g_i | D-data：分组与扩题、加权；D-param：选出要更新的参数块 |
| E 学生更新 | 修复、学生自己的成功、K 条示范混合训练 | θ_{r+1} |
| F 评测 | 选择只用合成的留出任务；dev140 对比 baseline | 独立成功率 |

## 2. 各部件的 v0 实现与依据

### S 合成练习（harness 的作用之一：增加监督的多样性和丰富性）

| 生成器 | 做法 | 针对的问题 |
|---|---|---|
| G1 换位置 | 同一场景、同一目标，把目标物体放到另一个能放它的容器里（同步修改所有相关初始事实） | 搜索：V2 里最大的失败类型 |
| G2 换目标 | 同一场景和初始状态，换成另一种 ALFWorld 任务类型或别的物体、容器。目标的 PDDL 形式照抄真实训练游戏，指令文本按环境原有机制生成 | 目标理解、动作前提（加热、清洗、冷却、两个物体、开灯看） |
| G3 出错状态 | 在 K 条示范中间真实执行一个受控错误（被拒动作、拿错物体、放错位置、一段无效搜索），让学生从那里接着做 | 出错后的恢复（V2：学生忽视被拒动作、重复错误） |
| G4 分支反馈（第二步加入） | 在学生的决策点上，harness 试执行若干候选动作，返回各自的结果 | 每个状态上更丰富的监督 |

合成任务的接纳条件：
- 用现有 Environment 能加载；
- 初始观察里的任务文本与新目标一致；
- 有成功见证：由 ALFWorld 自带的专家或规划器，或者 teacher，在 harness 里执行成功。见证只用于证明可解，不进入训练文本；
- reset 两次结果相同；
- 不与 dev140、valid_unseen 及其他留出集的任意一组重合（任务类型、物体、容器、场景都相同即算重合）。dev140 来自 valid_seen，场景与训练场景重叠，所以这条必须检查。

每个训练样本都带生成器标签。v0 跑完后逐个去掉一类生成器重新训练，看它对 dev140 的贡献，这就是"同步探索 harness 怎样增加合成监督最有效"。可行性验证由 Codex 实现（11-02 13:06 CST 开始，只写代码，不用 GPU 和 teacher）。

默认只用 K 个任务自己的场景（与 baseline 同等），是否允许其他训练场景的房间布局待用户确认。

### A 学生作答

- 每个合成任务 1 次 greedy 加 3 次采样，采样 T = 0.7、top_p = 0.95，harness 不变。
- 成功轨迹原样保留，不改写成 teacher 风格。
- 每个任务的失败率记为该错误条件的行为一致性。

### B 整体评价与最小修改（取代原部件 A 和 B）

输入：任务、学生完整轨迹，以及 harness 标注。标注逐步给出：是否被拒、前提是否满足（沿用 joint-review/2 的前提事实表）、看过哪些容器及看到了什么、是否重复、最终结果。

Teacher 输出结构化评价：
- 学生的计划（子目标序列，附证据步号）；
- 可保留的选择（与 teacher 不同但合理）；
- 走不通的位置与原因；
- 最小修改：最多 2 个修改块，每块是具体的环境动作。

Harness 闭环验证：
1. 重放到修改处，执行修改，**先重放学生原来的后续动作**；
2. 不成功时交还学生 θ_r 从修改后的状态继续；
3. 仍失败就把新轨迹交给 teacher 再评价，每条失败最多 3 轮。

只有成功才算修复。修改距离按动作 Levenshtein 距离记录，同样成功时取距离最小的。Harness 不透露未观察到的物体位置，"能否成功"由真实执行回答。

依据：
- E1（10-26）的开环修补只修好了 1/12 个搜索失败，所以必须闭环；
- CG probe：抽象提醒无效，具体命令 93% 被执行；
- V1b：teacher 亲自示范只占 3.4%；
- V2：逐步判断合法性会放行低效搜索，所以 v0 按整条轨迹的结果评价。

### C 错题集扩展

按 D 的结果，对一致的错误模式用 G1–G3 合成更多同类任务，学生作答，失败的走 B。扩题总预算两个版本相同，分配方式不同（见 D）。

### D 梯度分析：两个 variant，对应最终方法的两个版本

在本轮的 θ_r 上，对每个修复 episode 计算 LoRA 参数的梯度 g_i。loss 与训练相同，只算修改处的决策；关闭 dropout，不执行 optimizer step。

| 版本 | 怎么用 g_i | C 的扩题分配 | E 的训练 |
|---|---|---|---|
| **D-data** | 跨错题比较：CountSketch 压到 2,048 维，按余弦距离做 k-medoids（k ≤ 6）；一致性 = 组内平均余弦相似度 × 组大小；teacher 读每组的代表案例，写出错误模式 | 按一致性分配 | 一致性高的组权重更大；更新全部 LoRA 参数 |
| **D-param** | 跨参数比较：按 LoRA 模块计算梯度的信噪比（各错题梯度的均值范数 / 标准差），选出大而一致的参数块 | 各错误类别均分 | 只更新选中的参数块，其余冻结；样本权重均匀 |

两个版本共用 S、A，以及第一轮 B 的修复。从 C 开始分开。最终两个版本都在 dev140 上与 baseline 比较。

### E 学生更新

- 数据桶：修复 episode、扩题上的修复和学生成功、合成任务上学生自己的成功、K 条原示范。权重起点沿用 v0.1 §11.2：0.50 / 0.25 / 0.15 / 0.10。
- 修复 episode 监督整条验证成功的轨迹，跳过被拒动作和重复被拒动作（V2 构造规则）。修改处的 Thought 用前缀一致的理由标签器重写。
- 从 θ₀ 继续训练，LoRA 配置与 V2 相同。训练量按遍数定，只在少数几个 checkpoint 上选择。选择只用合成的留出任务，不碰 dev140。

### F 评测与比较

- dev140 在 hpg B200 上用 baseline 的同一流程跑：tree 46b8527，scripts/hpg_eval_adapters.slurm，greedy，BATCH_INVARIANT=1。
- K20 比较对象（dev140 成功数，3 个种子）：轨迹 SFT 78/78/90，AD 104/95/97，SmartAD 84/90/98，SAD 52；base 43，teacher 114。
