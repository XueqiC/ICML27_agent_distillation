# 修订项目方向：让蒸馏学生可靠替换原 Agent 中的大模型

2026-10-07｜研究判断与实验方案｜以用户提供的实验汇总为依据，未审计原始逐步日志

**建议主问题：在保留原有 harness 的条件下，怎样蒸馏出一个可以可靠替换教师、独立完成任务的小模型？**

暂定英文题目：**Drop-In Agent Distillation: Preserving Agent Performance under Model Replacement**。

这份文档替代上一版以“经验充分性”为中心的项目定位。下面严格区分已有观察、候选解释和待验证的新方法；标题不代表方法已经完成或新颖性已经确立。

## 1. 先纠正实验单位和项目边界

**K 是初始可信样本数，不是允许访问的任务数。** 在目前的数据组织中，一条样本通常是一条经过执行验证的教师轨迹。一个任务实例可以产生多条样本；将一条轨迹拆成多个步骤，也不能据此增加初始 K。

需要分别记录：初始样本 K、独立任务实例数、任务类型数、后续教师监督量、环境交互量、训练曝光量。已有实验只在种子样本关联的实例上继续探索，是一个额外的实验限制，不能当成 few-shot 的定义。

允许扩展以后，应称为“少样本启动的蒸馏”，并明确报告扩展量。如果后来取得了很多可信轨迹，不能仍然写成“总共只用 K 条轨迹”。

主实验固定原 harness H0，包括上下文组织、工具接口、状态记录、重试与终止规则。教师 T 被学生 S 替换，目标是提高 J(S,H0)，其中 J 是任务成功率或预先确定的任务效用。模型所必需的标准 API/chat-template 适配应正确实现并公平提供；不把故意接错接口作为研究现象。

部署不依赖教师或新增的外部规划器。训练时可以使用教师、环境验证和额外诊断，最终都退出。永久修改 harness 的方案可以作为对照，但属于另一个部署条件。

## 2. 我们自己的实验，实际上把故事限制到了哪里

以下数字来自用户提供的 10 月 7 日汇总：ALFWorld valid_seen 的 dev140；base 62/140，teacher 114/140。三份种子样本集不等于三个独立训练随机种子。

| 已有观察 | 目前可以支持的判断 | 目前不能推出的判断 | 下一步最有价值的检查 |
|---|---|---|---|
| 3–6 万监督 token 附近出现低谷，增加剂量后恢复 | 优化过程是实质混杂；官方配方在当前小数据设置中可能不合适 | 低谷由 harness 不兼容造成；这个剂量阈值具有普遍性 | 在已有检查点上对齐训练损失、独立局部决策质量、完整任务成功率 |

| 增益主要来自 base 不会、样本覆盖到的加热和冷却 | 新知识或技能覆盖确实解释了一部分收益 | 所有剩余失败都是“知道但不会用反馈” | 将技能缺失与已掌握技能的执行失败分开统计 |
| 粗类型覆盖相同的 k2s1/k2s2 为 86 对 59 | 粗粒度类型标签不足以解释表现；相差约 19.3 个百分点 | 原因必然是恢复分支覆盖或 harness 信息利用 | 检查类型内样本数、对象/布局、步骤、示范质量、关键反馈事件与训练稳定性 |
| M1a 探针未检出；低 K 下 I4 动作干预比 I3 建议更有效 | 局部知识探针与自主执行可能不一致；决策接口值得检查 | 全部知识已经学会；I4/I3 差异唯一证明 M2 或容量不足 | 重用干预后的续跑，检查修正一次以后能否持续独立执行 |

**最重要的限制：我们目前还没有证明“模型已经蒸馏得很好，但因为原 harness 而失败”。** 种子关联实例上的高拟合不是独立的模型能力指标；同样，低 K 的任务失败也可能只是缺知识、缺覆盖。

K20 与教师的平均差距约为 4.5 个百分点，K50 与教师平均相近。这既约束论文叙述，也提供一个有用对照：我们可以比较数据增加时，什么具体行为发生了改变。教师的 114 也不是环境的理论上限。

## 3. “模型蒸馏得好”与“接回 Agent 表现好”应该怎样定义

至少分开三个量：

1. **输出拟合**：独立历史上的教师响应似然或监督损失。
2. **局部决策质量**：给定相同合法历史，学生是否产生可执行、对任务有用的动作。不能用与教师字符串一致来代替；允许多条正确路径。
3. **自主执行效果**：学生从任务开始，在 H0 内持续行动到终止的实际结果。

其中任何两个都不能直接相减后称为一个有因果含义的“gap”。需要比较相同检查点在这些指标上的变化、排序，以及可控干预的效果。

从第一性原理看，如果学生在每个相关历史上，都与教师产生相同的、会影响后续执行的完整输出分布，在相同的 harness、环境随机规律和预算下，两套系统的轨迹分布也应相同。这里不只包括解析后的工具动作：如果推理文本会进入后续上下文或记忆，它也属于相关输出。因此不存在神秘的“接入后能力消失”。问题只能来自近似蒸馏在某些地方没有保留影响任务的行为。

需要具体检查的地方是：输出是否被正确解析；是否正确理解当前状态；自主行动是否把自己带到训练没有覆盖的历史；小错误是否被后续反馈纠正；不同错误对最终任务是否具有不同影响。

**可研究的张力因此是：局部平均指标可能掩盖少数会改变后续整段执行的错误。** 如果原 harness 中的状态、工具反馈、重试或记忆过程参与了这些错误的产生或恢复，才能进一步主张明确的模型—harness 交互机制。

## 4. 文献确认了痛点，也划出了创新边界

这里仅列与当前切口最近的工作，完整分类见此前的文献地图。

| 工作 | 已经提供的证据或方法 | 对本项目的约束 |
|---|---|---|
| Better Harnesses, Smaller Models [1] | 小模型直接接入强模型使用的 harness 会出现性能下降；调整上下文、工具和运行逻辑能够改善部分工作流 | 支持替换痛点；但并未证明这些小模型已完成高质量蒸馏 |
| Harness-Aware Distillation, HAD [2] | 明确研究教师和学生共享固定 harness；用教师有/无 harness 信息的动作对比及有效性过滤进行训练 | “固定 harness”“学习利用反馈”本身已经不是新贡献，必须正面比较 |
| SOPD [3] | 在学生访问的历史上取得教师步骤监督 | 学生状态分布偏移已有直接基线 |
| SmartAD [4] | 利用学生适配性选择教师经验 | “给小模型挑更适合的示范”不是新的概念 |
| FutureBridge-OPD [5] | 考察教师指导之后的学生续跑，并据此验证指导 | 仅增加“纠正以后让学生继续试”不足以构成创新；原方法的信息访问条件也需核对 |
| Harness-Zero [6] | 将额外训练辅助转成基础动作监督，部署撤除额外层 | 训练时有辅助、部署无辅助并非新的路线 |
| DAgger、AggreVaTeD、DART [7–9] | 学生诱发的状态、后续代价、恢复示范分别已有经典研究 | 分布偏移、重要步骤加权、扰动恢复不能单独包装成新发现 |

HAD 的直接相关性尤其强：它不是只把 harness 文本附在输入上，而是训练模型对 harness 信息作出相应决策。[2] 因此，我们需要回答一个更细的问题：**这些训练以后，哪些局部决策仍无法转化为原系统中的可靠执行，为什么，用什么可验证的监督可以补上？**

新方法如果只是把 HAD 的偏好标签换成成功标签，或者给 DAgger 加几个错误样本，贡献可能较小。高潜力来自明确的新机制、能预测实验结果的诊断，以及由此推导出的蒸馏方法共同成立。

## 5. 我建议优先检验的机制

### 5.1 主假设：成功路线已学会，偏离后的反馈响应仍没有学稳

少量成功示范可能足以教会正常路线，但对工具未生效、对象状态不同、已有动作重复失败等情形覆盖不足。学生第一次小错之后，H0 返回新的信息；学生若仍沿用先前路线，小错会继续传播。

这是一条候选解释，不是现有日志已经证明的事实。它与我们已有结果相容：

- 反复训练原样本可以学会正常路线，因此高剂量和训练实例拟合很有效。
- 同样关联实例上继续成功执行，难以自动产出更多恢复监督。
- 相同粗类型的不同轨迹可能包含不同前提、反馈与执行步骤，从而产生很不一样的迁移效果。
- 直接给动作可能绕过一次错误决策，但给建议未必能让学生自己完成同样转换。
- K50 可能已经覆盖足够多有关情形，所以当前分布上的平均差距消失。

每一条也都有别的解释。尤其最后一条不能反推“K50 已覆盖恢复事件”；必须检查实际样本和轨迹。

### 5.2 必须正面对照的解释

| 候选原因 | 应该出现的证据 | 最有力的反证或替代解释 |
|---|---|---|
| 基本知识/技能缺失 | 简洁、信息充分的局部问题也答错；补普通新任务即改善 | 局部能力已好，只有原始上下文或自主历史差 |
| 原生上下文中的信息使用失败 | 相同事实仅改变呈现方式即可提高决策；教师受影响明显更小 | 改写实际增加了事实、子目标或建议，不能归因呈现方式 |
| 学生状态覆盖不足 | 教师历史上好，学生诱发历史上差；普通学生状态监督消除差距 | 覆盖相同历史以后仍存在系统性差距 |
| 小错误后无法恢复 | 同一错误由教师续跑能恢复，学生续跑失败；反馈或状态处理干预能改变该关系 | 初始错误已经不可恢复，或只是通用能力差异 |
| 协议或实现错误 | 仅修复序列化、解析、截断配置就恢复 | 这首先是工程问题，不应作为核心蒸馏机制 |

这些原因可以共存，不能把几种干预的救回比例直接相加，声称完成了互斥的因果分解。

### 5.3 few-shot 可能怎样加剧它

K 小首先会减少正常知识覆盖，也可能减少罕见关键反馈的出现。重复监督 token 主要增加已有样本的曝光，不会自动生成新的环境分支。

但“低 K 成绩更差”并不能证明反馈机制被 few-shot 特别放大。需要在剂量合理、技能覆盖可比的条件下，检验关键反馈后的错误或恢复差距是否更大，以及针对这类事件的监督是否有额外收益。高 K 的总成功率接近上限时，不能仅凭低 K 增益更大就宣称交互效应。

## 6. 第一批实验：先把问题打实

### A. 重用现有模型，建立一张贯通局部与任务的表

对象：teacher、base、K5/K20/K50 的足剂量学生，尽量保留三份样本集；加入少量已有低谷检查点分析剂量效应。不先启动大规模新训练。

逐项对齐：

- 独立历史上的局部动作质量与响应损失。
- 原 H0 下任务成功率。
- 教师成功但学生失败、学生成功但教师失败的配对任务。
- 第一次实质偏离的位置，以及它之后的工具反馈、重复动作和最终结果。
- 已有 I3/I4 干预之后，学生是否能够持续独立推进。

历史评测库同时包含教师与学生实际访问的合法历史，并对所有模型使用相同的固定历史集合；不能给每个模型一套难度不同的历史再比较局部质量。训练、机制发现和最终测试分开。dev140 已经被大量使用，应继续作为开发证据，不能改称封存测试。

关键结果并不预设为“拟合好而执行差”。若模型在独立局部决策上仍差，先承认蒸馏能力本身不足。

### B. 用交叉续跑区分第一次错误与之后的放大

从合法执行中取得快照，保存环境状态与完整 H0 状态，包括历史、记忆、计数器和剩余预算。无法可靠快照时采用确定性前缀重放；无法复现的情形不用于该因果比较。

在完全相同的快照上，固定教师和学生各自给出的下一步候选，做四种执行。候选包含 H0 实际接收的整步输出；如果推理文本会写入后续历史，也必须随这一步一起保留，不能只换动作却悄悄保留另一个模型的历史：

| 下一步来自 | 后续由谁独立执行 | 记号 |
|---|---|---|
| 教师 | 教师 | R_TT |
| 学生 | 教师 | R_ST |
| 教师 | 学生 | R_TS |
| 学生 | 学生 | R_SS |

R 是从该快照开始的成功率或任务效用；随机环境采用配对随机种子并对关键结果重复。

比较：

- 教师续跑时，一次学生动作带来的差异：Δ_T = R_TT − R_ST。
- 学生续跑时，同一次替换带来的差异：Δ_S = R_TS − R_SS。
- Δ_S − Δ_T 为这组干预下的交互量，不是整个任务差距的可加分解。

例如，教师可以从学生那一步继续成功，而学生不行；给学生教师那一步又能成功。这比笼统的“学生不会执行”更具体地显示了局部决策与后续策略的配合问题。保留负值和反例，不预设教师动作永远更优。

**这仍然没有单独证明 harness 原因。** 还要对实际存在的反馈、记忆或重试组件做干预，检查它们是否改变上述关系。不能在 H0 没有记忆压缩或循环提示的情况下，凭空讨论这些组件失效。

### C. 同信息的输入对照，定位原 harness 中的具体负担

在相同状态下，比较原生输入与只做格式整理的输入。后者不得补充隐藏事实、正确动作、额外观察或规划。教师和学生都做同样对照。

如有改善，它说明信息呈现影响了决策；只有结合具体字段、反馈事件和跨模型对照，才支持更窄的机制。它不证明学生完全掌握任务，也不能把整理后的输入作为“原 harness 不变”的主结果。

对于确实改变决策含义的反馈分支，必须用真实执行产生不同状态，不能只把 observation 中的“成功”改成“失败”而不改变隐藏环境。

### D. 补齐扩展基线，再判断是否需要新蒸馏法

第一轮从 K5 的三份初始样本集开始，比较：

1. 现有足剂量 Seed-SFT。
2. Grounded Augmented-SFT：新实例上的环境验证教师轨迹。
3. 扩展实例上的 SOPD/黑盒 DAgger：在学生状态上取得教师步骤监督。
4. 固定 H0 下的 HAD 适配。
5. 下节的新方法原型。

SmartAD 加入正式近邻主表；使用相同候选数据上的训练对照分辨学生适配与新监督的贡献。已有官方 baseline 完成必要收尾，但不再成为全部研究资源的中心。

**所有主比较都应有相同的新任务访问权限。** 不能让新方法自由扩展而把基线限制在种子关联实例。历史上受限的实验可以保留为单独设置。

教师 token、环境步、不同轨迹数和训练 token 分开报告。在可操作的固定预算上比较，同时给合理训练剂量；不把某一个数字相同宣称为所有资源完全公平。此前约 40 万监督 token 可作为起点，而不是对所有新数据配方都有效的定律。

若普通扩展就解决了全部问题，应该接受这一结果，不能继续声称该分布上存在特殊迁移障碍。

## 7. 优先发展的蒸馏方法原型

工作名可暂用“闭环分支蒸馏”，但先不要把名称当成贡献。核心设计是：**用原 H0 中经验证的动作—反馈—后续行为来定义监督，而不是只用一条教师回复定义正确性。**

### 7.1 在原系统中发现训练位置

学生按部署方式执行训练任务，发现真实的工具失败、前提遗漏、重复无效动作或状态更新后的决策分歧。正常成功位置也保留，避免训练集只剩异常情况。

诊断只决定哪里值得检查。教师/学生分歧并不直接说明学生错误，低似然也不直接说明有价值。

### 7.2 构建合法执行分支

在可重放状态上，由黑盒教师与学生提出候选。执行候选后记录真实反馈与 H0 变化，并由学生续跑。必要时教师续跑用于分辨目标本身有问题，还是当前学生暂时不会后续步骤。

对存在不同真实前提或结果的相近情形，保留一组经验，明确呈现何时应继续、何时应检查、何时应修正。例子必须来自当前环境支持的行为，不能捏造新工具或不可能的错误。

### 7.3 按可验证的执行作用构造目标

- 合法且能够推进任务的不同回复可以同时保留，不把偏离教师措辞当错误。
- 只凭接口合法不能认定回复正确；应结合可验证的状态变化或任务结果。
- 只凭一次学生续跑失败，也不能认定教师策略不可学习。当前续跑结果主要用于优先级和课程安排；保留经过验证但暂时较难的教师示范。
- 对会引起后续持续失败的决策，增加训练关注；正常成功路径作为锚点，防止只学会修复而损害基本能力。

与 HAD 的主要设计差别在于：候选质量由原系统中的执行证据决定，不把是否看到 harness 信息本身用作质量代理。但这一差别只有在解决了可重复的剩余错误时才有研究价值。

### 7.4 训练模型自身，在部署时保留 H0

训练输入使用 H0 原生可见信息，输出使用其原生动作协议。新增的是训练监督，不是在推理时持续添加提示、教师或新规划层。

实现可从对验证候选的加权蒸馏开始。例如，对输入 x 和有限的已验证完整回复集合 Y+(x)，可以研究目标：

\[
\mathcal{L}_{\mathrm{branch}}
=-\mathbb{E}_{x}\left[w(x)\log\sum_{y\in Y^+(x)}p_\theta(y\mid x)\right]
+\lambda\mathcal{L}_{\mathrm{anchor}}.
\]

这里 y 是模型原生完整回复，候选以终止符区分；概率来自学生，不要求黑盒教师 logits。Y+ 是经过有限验证的候选集合，不是所有正确策略的真值集合。w 需要由可复现的后续影响估计构造，并限制高方差权重。候选数、长度、验证预算均需控制。

这个式子只是可实现的原型：单一正例时接近加权 SFT，不能凭公式宣称创新。新的目标是否必要，要由同数据的普通 CE、多解 CE、后续代价加权模仿及方法完整版本的比较决定。

### 7.5 最关键的消融

| 对照 | 排除什么解释 |
|---|---|
| 相同分支数据，普通 SFT | 增益是否全部来自额外数据 |
| 相同查询与交互预算，普通 SOPD | 增益是否只是访问了学生状态 |
| 相同 H0 下 HAD | 已有 harness 信息利用方法是否已足够 |
| 普通失败恢复数据、相近难度数据 | 成组分支是否超出普通困难样本挖掘 |
| 回报加权模仿或可比的直接 RL | 是否只是已知的后续代价学习 |
| 原型去除结果验证、去除成组反馈、去除多解 | 明确是哪一个设计带来收益，不把全部组件捆成黑盒 |

如果普通 SFT 在相同分支数据上就达到完整方法效果，方法贡献应落在数据构造与机制，而不是虚构一个必要的新损失。如果 SOPD/HAD 已经解决全部问题，也应据此调整项目。

## 8. 一条可以成立的高潜力故事线

以下是研究叙事的目标版本，不是现成的摘要结论。

**实践问题。** 一个大模型已经在某个工具与执行系统内工作。我们希望换成便宜的小模型，同时保留已有系统。

**已有认识。** 轨迹蒸馏、学生状态监督和 harness-aware 方法已显著提高小模型能力。我们自己的实验还发现：在当前 few-shot 设置中，训练剂量与基本覆盖能解释大量原本看似高级的失败，普通 SFT 可以很强。

**需要检验的剩余问题。** 局部决策质量改善是否总能保留系统能力？在剂量与覆盖控制以后，是否仍有少量关键错误因后续反馈处理不当而被放大？这一机制是否能解释此前无法由粗任务类型解释的样本集差异？

**机制贡献。** 用同状态交叉续跑和具体 harness 干预，定位错误是怎样传播或被纠正的，并预测哪些训练经验能改变该过程。few-shot 是机制更可能暴露、也更有实际价值的场景，不先假定其必然放大。

**方法贡献。** 据此构造以真实执行分支为监督单位的蒸馏，使小模型在原输入、原工具和原控制流程中学会合适的后续行为。

**部署结果。** 同一 H0 下，学生在独立任务中保留更多教师成功任务，降低失败后的持续失控，同时保持或提升总成功率；教师和训练辅助退出。至少在第二个实际工作流中重现，不要求一个学生泛化到所有任意 harness。

潜在影响来自“怎样训练一个组件，使替换之后整个交互系统仍可靠工作”这一可迁移原则。它需要强近邻比较、因果证据与独立复现来支撑；少样本标签、一个更难 benchmark 或一个新模块名称都不能替代这些证据。

## 9. 执行顺序与决策点

**第一优先：已有日志与检查点分析。** 完成局部/整体指标对齐、教师学生成功集合、首次偏离及 I3/I4 续跑分析。这一步决定候选机制是否真的存在，不需要重新训练整张主表。

**第二优先：最小分叉实验与扩展基线并行。** 先用 K5 三份样本集检验，再把同一诊断作用于 K20/K50。给扩展 SFT 和学生状态监督相同访问权限。

**第三优先：针对已确认机制训练原型。** 主训练在 H0 内完成，新增模块留在训练阶段。直接比较同数据 CE、SOPD 和 HAD，避免先做大量最终无解释力的工程。

**第四优先：外推验证。** ALFWorld 未见场景有助于检验覆盖泛化，但“更难”本身不是 harness 机制。第二工作流应具备可验证结果、可恢复执行状态，以及与机制相关的真实工具反馈或控制过程。选择它是为了检验机制，不是为了保证出现至少 10 个百分点的缺口。

结果分支：

- 若普通扩展 SFT 消除差距：说明当前工作流主要受剂量与覆盖制约，保留扎实结论，不宣称特殊障碍。
- 若 SOPD 消除差距：主要是学生状态覆盖问题，需要超出这个已知机制才继续新方法主张。
- 若 HAD 消除差距：其监督已满足当前需要；few-shot 复现本身不足以支撑顶级贡献。
- 若存在可定位、可干预、可跨设置预测的剩余错误，且原型能在 H0 内解决：进入完整方法、理论和第二环境阶段。
- 若只修复接口就消除差距：立即修复，作为实现控制，不膨胀成研究发现。

统计上按独立任务和初始样本集报告不确定性，不能把同一任务内很多步骤当作独立样本。最终主张还需要独立训练随机种子和未用于诊断、调参、生成训练数据的评测。
