更新我们的weekly report我们现在把项目明确为：**固定工具和 API 条件下，面向小模型自身能力的交互策略蒸馏。**

核心问题是：

> **面对同一个任务、使用同一套工具，最适合教师的交互方式，是否也是学生应该学习的方式？如果不同，怎样通过蒸馏，让学生学会适合自己的策略，并独立完成任务？**

这个问题保留了我们希望触及的小模型 Agent 设计原则，同时把可改变的对象收紧到了训练方法和学生行为。

**首先，明确哪些固定，哪些可以学习。**

| 固定的系统条件 | 学生可以学习的行为 |
|---|---|
| 工具集合、API、参数语义和权限 | 调用哪个工具，使用什么合法参数 |
| 工具返回与环境状态变化规则 | 什么时候查询、操作、检查或重试 |
| 原有上下文和记忆机制 | 怎样利用已有历史、反馈及合法的记忆操作 |
| 执行与终止规则、共同预算 | 怎样安排操作顺序，什么时候继续或结束 |

因此，工具不变，并不意味着调用路径必须相同。我们主要改变学生参数，让这些选择成为模型自身的能力。

**K 仍然是初始可信样本数量。** 可以扩展任务实例、教师监督和真实交互，但新增量必须单独报告。部署时只使用训练后的学生与原有系统。

**整个故事，从“教师的成功方式是否适合学生”这个问题展开。**

一条教师轨迹展示的是：具有教师推理、记忆和纠错能力的模型，怎样使用工具完成任务。

教师可能从较长历史中恢复当前状态，推断操作结果，省略一次查询，然后继续执行。学生面对相同历史，未必能可靠完成这些推断，但它可能通过已有 API 重新取得状态，再作出正确决策。

这里有一个值得检验的核心命题：

**同一次交互的价值，不仅取决于任务和状态，还取决于执行模型的能力。**

例如，原系统已经提供状态读取接口：

- 对教师，重新读取可能没有价值，因为它已能从历史准确判断。
- 对学生，重新读取可能减少记忆或推断负担，提高后续成功率。
- 在状态已经很清楚时，学生也应直接推进，避免浪费调用。

两者拥有相同的初始信息和工具权限。学生通过自己的合法动作取得不同的后续观察，这是策略的一部分，额外成本也必须计入。

**这使我们的研究超出了“怎样让学生少犯错”：我们要研究学生应该怎样使用外部能力。** 信息获取、状态复查、工具组合、错误恢复和终止判断都在范围内；恢复只是其中一种行为。

**对小模型 Agent 设计的潜在影响，是将交互方式本身作为需要学习的能力。**

在固定接口下，我们希望回答三个具体问题：

1. 哪些判断学生可以直接完成，哪些判断值得先调用已有工具取得帮助？
2. 什么情况下增加交互能够弥补推断或记忆困难，什么情况下只是增加成本？
3. 随着学生能力提高，原本必要的查询和检查是否应该减少？

如果能形成可预测的答案，设计者就不必默认把强模型的调用路径当成小模型的唯一训练目标。**蒸馏可以保留任务解决能力，同时允许学生采用不同的实现方式。**

但这是一条待验证的研究主张，不能预设所有小模型都需要更多交互，也不能承诺固定工具能够补偿任何能力不足。

**我们已有的实验，为这条主线提供了起点，也划出了边界。**

| 已有结果 | 在新故事中的位置 |
|---|---|
| 低剂量出现低谷，补足剂量后普通 SFT 很强 | 首先排除优化不足，确保新方法面对强基线 |
| K20 为 107.7/140，K50 为 114.7/140，教师为 114/140 | 当前分布上，普通蒸馏能够达到教师平均水平；不能预设普遍迁移障碍 |
| 种子关联实例拟合高、纠错信号少 | 需要开放新的实例和执行状态，避免反复收集已经学会的行为 |
| 相同粗类型覆盖，两个样本集得到 86 和 59 | 值得检查具体知识与交互方式的差别，不能只用任务类型解释 |
| I4 直接给动作比 I3 给建议更有效 | 提示我们检查形成决策与后续执行的困难，但还不能唯一确定原因 |

所以，**我们尚未证明学生需要不同策略**。普通知识覆盖、示范质量和训练过程仍然是必须控制的解释。

新研究要从这些结果继续往下问：数据增加以后，学生究竟学到了更多事实，还是学会了更合适的交互？哪些失败可以通过改变原生工具的使用方式解决？

**方法方向随之确定：构造并蒸馏对学生有效的交互策略目标。**

第一版可以采用一个迭代过程：

1. **建立足剂量学生起点。** 用 K 条可信样本完成普通蒸馏，保留正常成功能力。
2. **收集学生的真实执行。** 找到状态判断、反馈使用或操作安排上的困难，也保留正常成功位置。
3. **产生原接口内的替代交互。** 教师结合学生的困难提出候选，例如先使用已有查询，再根据真实返回继续。学生自己找到的有效路径也可以保留。
4. **验证对学生的实际作用。** 从相同状态执行候选，让学生自主续跑，记录成功率和完整成本。
5. **把这些目标蒸馏进学生。** 学习什么时候直接推进、什么时候采用替代交互，以及得到不同返回后怎样行动。

训练监督必须同时包含“应该查询”和“不必查询”的情形，避免模型学成机械地每步多检查一次。

最终不能靠运行时教师告诉学生正确动作，也不能持续给出针对当前任务的正确计划。**学生必须在原生输入与动作协议下，自主选择并执行学到的策略。**

当前学生续跑失败，也不等于该策略永远学不会。验证结果用于调整训练优先级，不能把所有暂时困难的正确经验都删掉。

**我们的创新目标，需要比“挑学生喜欢的轨迹”更进一步。**

SmartAD 已经根据学生似然选择教师候选；HAD 已经训练学生利用固定 harness 的信息；FutureBridge 已经通过学生续跑验证教师指导。它们都是必须正面比较的近邻。[ACL Anthology](https://aclanthology.org/2026.findings-acl.1349/?utm_source=chatgpt.com)

我们要争取的新证据是：

- 某类原生交互的实际价值，确实随执行模型改变。
- 这种差异能解释或预测哪些监督对学生有用。
- 据此调整蒸馏目标，能让学生自主学到更合适的策略，效果超出普通数据扩展、学生状态监督和已有学生适配方法。

固定接口是研究边界，本身不构成创新。新损失函数也不能代替这条证据链。

**接下来最关键的实验，是“执行模型 × 交互方式”的交叉比较。**

从完全相同的环境与 harness 状态出发，比较两种合法交互，再分别让教师和学生独立完成：

| 初始交互方式 | 教师续跑 | 学生续跑 |
|---|---|---|
| A：直接推进 | 教师采用 A 的结果 | 学生采用 A 的结果 |
| B：原生替代交互，例如先查询 | 教师采用 B 的结果 | 学生采用 B 的结果 |

重点看：**B 对学生是否有稳定收益，而对教师收益较小，甚至因成本而不值得。**

实验必须扣除前缀消耗的预算，区分新事实、已有事实的重新获取，以及单纯增加调用或思考时间的作用。教师接近成绩上限也可能导致增益小，需要单独处理。

这个实验中的初始交互是诊断干预。最终方法的主结果，则必须让学生从任务开始自己决定是否采用 B。

**下一轮任务按这个顺序推进。**

| 顺序 | 要做什么 | 必须交付什么 |
|---|---|---|
| 1 | 梳理原生接口与执行限制 | 明确哪些查询、检查、记忆和重试行为真正可实现 |
| 2 | 重分析已有模型和轨迹 | 对齐局部质量、完整成功率、首次偏离、I3/I4 续跑及样本内容差异 |
| 3 | 做上述交叉实验 | 找到至少一类可重复的、对学生有价值的原生替代交互 |
| 4 | 补扩展基线并训练原型 | 公平比较普通扩展 SFT、学生状态监督、HAD、SmartAD 和新目标 |
| 5 | 验证自主性与外推 | 检查何时查询、如何使用返回，以及新实例、不同学生和第二工作流上的效果 |

第一轮从 **K5 的三份初始样本集和一个固定新增预算条件**开始。K20/K50 用作数据条件对照；另外增加真正的学生能力对照，不能把 K 的变化当成模型容量变化。

所有方法拥有相同的新任务访问权限。新方法还必须有**相同数据上的普通 SFT 对照**，才能区分收益来自新经验，还是新的蒸馏机制。已有官方 baseline 按原计划收尾，保留为此前设置的结果。

这版项目最终希望建立的主张是：**在既有工具生态中，小模型需要学习适合自身的交互策略；蒸馏应当能够识别并训练这种策略，使学生通过原有接口自主达到任务目标。**
