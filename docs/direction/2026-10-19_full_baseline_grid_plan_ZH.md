## 1. 统一设定（所有方法相同）

- **网格。** $`K\in\lbrace1,2,5,10,20,50,100\rbrace`$ × 支持集 s0–s2，共 21 格。每格使用同一组可信示范（嵌套关系见分析文档 §1.3），训练 seed 为 0。
- **学生与教师。**
  - 学生：Gemma-4-12B-it（`707f0a3b`），thinking 关闭，每步最多 1,024 个 token。
  - 教师：gpt-6-luna，只能拿到文本。
- **Harness。** H0 不变：ReAct 格式，每轮列出合法动作，40 步上限。只有某个方法的机制本身就是改 harness 时才例外，见 §4 的待定问题。
- **探索。** 只能在这 $`K`$ 个训练任务上探索。若方法在这个约束下失败（例如没有可用的纠正而停止），记为方法本身的行为，不放宽协议。
- **评估。** dev140、batch-invariant、greedy、seed 0。每个检查点都先过 HF/vLLM 等价性检查；**每个**轮次都评估，不在 dev 上挑选。
- **配方。** 用官方 repo 的超参。batch 按已登记的规则缩小：$`b'=\min(b,\max(1,\lfloor N/8\rfloor))`$。所有偏离都在 `baselines/*/DEVIATIONS.md` 中登记后才运行。
- **教师调用。** 每个方法、每个格子设硬上限，并记入 ledger。

## 4. 需要用户决定的问题（附推荐）

- **Q1 SAD 需要教师 logits。** 黑盒教师给不了。
  - 推荐：用教师 token 的 one-hot 分布代替。此时 $`\mathrm{KL}(\mathrm{onehot}\Vert p_S)`$ 就是交叉熵，是黑盒条件下 SAD 损失的极限形式；推理段/动作段掩码和 curriculum 保留。
  - 备选：不跑。
- **Q2 HAD 的 harness 比 H0 多出状态跟踪和行为监控，论文也是带 harness 评估学生的。**
  - 推荐：只给 HAD 实现论文的 harness；学生在该 harness 和 H0 下各评一次，公平比较用 H0 下的数字。
  - 教师调用按论文的 250 次更新 × 60 个状态 × 2 次设上限，每格约 3 万次。
- **Q3 Chain-of-Agents 需要多 agent 教师系统。**
  - 推荐：按论文的角色设计，用 gpt-6-luna 搭一个多 agent 系统生成轨迹，用 CoA 的过滤规则筛选，再用官方 repo 做 SFT + DAPO（只在 $`K`$ 个训练任务上做 RL），并单独报告这个多 agent 教师自己的 dev140 成绩。
  - 备选：把单 agent 教师轨迹当作 CoA 轨迹，只做 SFT + DAPO。
- **Q4 AgentDistill 的机制是给学生加教师写的工具，会改变动作接口。**
  - 推荐：工具只能组合合法动作，每次调用在环境中执行，所执行的步数计入 40 步上限；结果标注为"接口不同"。
  - 备选：判为不适用、不跑。
- **Q5 GAD 是为单轮任务设计的。**
  - 推荐：把学生在 $`K`$ 个训练任务上到过的每个历史当作一个 prompt，向教师要同一历史下的回复；判别器逐回合打分，GRPO 逐回合做组采样。
