# v0.14 理论与执行包：理解笔记

收到时间：2026-10-09 22:35 CDT（Discord）。原包在 `docs/direction/v014_handoff/`。
本笔记是我读完全包后的理解、它和 v2 方向（Same Tools, Different Policies）的关系、它和我们已有代码与结果的对照，以及需要你拍板的问题。

## 1. 一句话

v0.14 把问题从“学生该学什么交互策略”上升为：

> **相对于给定的学生、给定的学习过程和任务族，环境（教师、工具、回放、真实交互、任何反馈通道）必须向学生传递哪些信息，训练后的学生才能在真实任务上做好？**

核心对象是**续跑响应函数** g(y)：学生收到一条反馈 y，执行一次真实参数更新，再按事先声明的参考流程把剩余训练跑完，最后独自部署，得到的期望真实成绩。它不是训练损失，不是教师置信度，也不是冻结学生的动作续跑分数。

定理 7 说：两个反馈来源在“任意一处替换、后面接声明好的训练尾巴”的意义下可互换，**当且仅当**它们对所有这类 g 的期望相同。之后所有结论（充分统计量、近似宽度、复杂度、证书、方法）都围绕这同一个对象展开。

## 2. 逻辑链

| 环节 | 问的问题 | 对象 |
|---|---|---|
| 可执行性 | 学生能执行什么 | 学生的策略类 Π（观察权限、记忆、表示、执行约束）及其与参考类的差距 |
| 可识别性 | 允许的实验能揭示哪些决策相关的事实 | 后验支持内的决策歧义 |
| 学习后果 | 反馈怎样变成能力 | 反馈 → 真实更新 → 剩余训练 → 部署 |
| 充分性 | 哪些区别可以丢掉 | 续跑响应等价 |
| 复杂度 | 需要多少统计量、什么阶 | 张成维数、一致逼近宽度、更新复合 |
| 可验证 | 有限数据能否检查 | 特征误差、抽样、覆盖、迁移项 |
| 方法 | 怎样获取和编译反馈 | CED：按真实学习后果选择反馈接口 |

## 3. 对我们最有用的几条结论

- **命题 1：三项分解。** 学生与参考最优之间的差距 = R_rep（策略类本身的限制）+ R_info（数据没给够信息）+ R_alg（信息在，但没学会）。这正好给已有现象一个归类框架：低剂量低谷属于 R_alg；种子集内容不同导致的差别（相同粗类型覆盖，两份样本集 86 vs 59）属于 R_info；学生做不到教师那种历史推断属于 R_rep。命题 3 补充：对已有数据做改写或生成，不能降低 R_info，只能降低 R_alg。
- **定理 4：完美教师示范也可能不够。** 教师看得到隐状态 s，学生的上下文是混叠的。被动示范在两个世界里分布完全相同，所以任何只用示范的学生，最坏遗憾至少是 Δ。如果允许在训练环境里 reset、执行动作并观察结果，大约 log(1/δ)/(8Δ²) 次查询就够，下界也是同阶。
  **这其实是 v2 核心命题的形式化**：教师能从长历史推断状态，学生不能，于是教师的最优路径不等于学生的最优路径；学生的最优选择取决于它自己执行动作后的结果，而教师示范从来不展示这些结果，必须用学生侧的实验来确定。注意 v2 的“混叠”来自能力限制而不是观察限制，但在 v0.14 里两者都算 Π 的限制。
- **命题 5：静态评价相同，不代表蒸馏效果相同。** 两个数据源让每个学生策略和教师的得分都一样，蒸馏出来的学生却差 1/40。“数据好不好”要看训练后的学生，不能看教师成功率或轨迹质量。
- **命题 6：** 平均梯度相同、方差更低，不代表训练后更好；换一个目标函数，偏好方向就会反过来。
- **定理 11–17：** 仿射或频率学习器下，需要匹配的信息是部署长度 N 以内的联合矩，并有严格层级（奇偶构造在每一阶都有常数差距）；非线性更新会放大所需阶数（定理 17）。这些是限定模型里的精确结果，文档自己说明不能直接搬到 Gemma/AdamW。
- **定理 18–20：** 怎样用有限次真实分叉实验来选反馈来源并给出保证。定理 20（在真实状态上做自适应审计）的代价是：4 个候选、δ=0.05、半径 0.1，**每个候选需要 1016 次独立训练副本**。在 12B 上做不到，文档把它定位成可选的 gold 对照。

## 4. CED 方法与实验规模

- **三个主分支：** 获取（查什么、在哪查）、编译（同一批证据怎样写成训练目标）、覆盖与迁移。另有一个可选的诊断分支：耦合，即保持边缘分布不变，只改分组或顺序。
- **选择标准：** 在学生的真实快照上分叉，执行真实更新、参考训练尾巴和真实部署，比较候选与参考的有符号优势。需要预先区分两个目标：保真（接近参考）和提升（超过参考）。
- **代理梯子（从便宜到贵）：** 教师成功率 → 学生损失 → 梯度 → GRACE/LESS → 冻结学生续跑分数 → 短尾真实更新 → 学到的响应预测器 → 全尾 gold。
- **pilot：** 3 个父 checkpoint × 4 个候选 × 2 次抽样 × 尾长 {1, 8} 步，每个 fork 评 8 个任务。合计 96 次学习执行、768 个 episode。
- **主实验：** K=32/任务族；6 个主臂 × 5 seeds × 2 个环境（ALFWorld + AppWorld）= 60 次训练。再扩展到 K∈{4,8,16,32}，并做 held-out 族、配方、域。
- **Baselines：** teacher SFT、on-policy/DAgger、cost-sensitive/LOLS、LESS/GRACE 梯度选择、梯度或轨迹匹配、MetaOPD（2610.11989，10-08 新出）、FutureBridge-OPD、HaDES/Behaviour Distillation。

## 5. 和 v2 方向的关系

v0.14 没有提“交互策略”，但两者可以合并，并不冲突：

- **v0.14 是理论层：** 说明为什么教师路径不一定是学生该学的（定理 4 + 命题 5），并给出“对学生有用”的判别标准（训练后果 g）。
- **v2 是一个具体的编译分支：** 候选 provider = 教师原路径 vs 学生适配的交互目标（先查询，或直接推进）。
- **关键差别：** v2 的 E2（同一状态做 A/B 前缀，再让冻结的教师或学生续跑）在 v0.14 里只是代理梯子上的“冻结学生续跑分数”一档。v0.14 的金标准要求真实参数更新、训练尾巴和部署。所以 E2 可以保留为便宜的诊断，但方法的选择标准要换成更新后果。

## 7. 我看到的问题（需要你拍板）

1. **K 的口径与天花板（最重要）。** v0.14 的主 K 是每个任务族 32 条。ALFWorld 有 6 类任务：如果每类算一个族，就是 192 条；即使整个 ALFWorld 只算一个族，K=32 也落在我们的饱和区（Seed-SFT K20 107.7，K50 114.7，教师 114）。主对比要求比最强 baseline 高 0.03（约 4/140），在天花板附近几乎测不出来。我们数据里真正有差距的区间是总量 K≤10。另外，ALFWorld 只有 6 类任务，held-out 族迁移的证据会很薄。
   建议二选一：ALFWorld 按总量计 K，主 K 定在 5–10；或者把主战场放到余量更大的 AppWorld。
2. **pilot 的测量功效。** 1 步或 8 步 LoRA 更新对 ALFWorld 成功率的影响，大概率小于评估噪声：每个 fork 只评 8 个任务，二值成功率的标准误约 0.17。我们的剂量实验还显示低剂量是负效应（低谷），所以短尾很可能和长尾排序相反。这正是 v0.14 §13.4 要测的现象，但 pilot 要设计成能看到它。
   建议：fork 评满 dev140（batch-invariant），尾长加上 32 步和全长。
3. **规模与 baseline 规则。** 6 臂 × 5 seeds × 2 环境，加上 fork 面板、有限理论面板和 6–7 个新 baseline。其中 MetaOPD 和 FutureBridge 需要教师 logprob，只能做标注的 adaptation，这和“只用完整官方代码”的规则冲突；HaDES 是进化搜索，代价很高。现有的 ETO/IPR/LEAP/AgentGym/Kang 都不在它的列表里，只能作为旧设定的结果。
4. **新颖性风险。** 审计自己写得很清楚：组件都是经典工具，整合是否新尚未确立。HaDES（用训练后的环境回报优化数据）、MetaOPD（经真实更新学权重）、FutureBridge（用续跑结果门控）已经占了大部分直观卖点。论文要站住，需要一个“只有这条链才能得到的结论”，目前还没有。
5. **seed 数。** pilot 要 3 个 seed、主实验 5 个，和我们“探索期单 seed”的约定不同。以哪个为准？

## 8. 我建议的第一步（不占用大量 GPU）

a. 写一张 v0.14 → 现有代码的映射表（本笔记 §6 的展开），明确 G0–G3 中哪些已满足。
b. **restore audit：** 取一个已有 LoRA checkpoint，保存完整状态，在新进程中恢复，续跑 8 步，比较参数哈希、损失和动作。1 GPU，约 1–2 小时。
c. 用实测吞吐（更新、存档、恢复、vLLM LoRA 评估）给 fork pilot 做成本预测，再定 pilot 规格。
d. 先在已有数据上做命题 5 式的分析：教师成功率和局部决策质量，与训练后学生成绩之间是否相关（已有 K5 的三个种子集和 K 网格）。不需要新的 GPU 时间。
