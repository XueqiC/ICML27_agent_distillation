tasks in all four rollouts. This leaves no failures for `P0_K20`; it is not a
negative finding about repair. M0c implements two separately reported branches
authorized in the current instruction: `P1_U_mech` with the same SFT adapter,
and `P0_K0` with the configured base student. The checked-out preregistration

requires `--branch {P0_K20,P1_U_mech,P0_K0}` with no default. Finalization cannot
change the source branch. Case records, ledgers, manifests, exports and probe
results carry branch/protocol metadata; immutable referenced execution and
LearningEpisode payloads retain their existing schemas and content IDs.

|---|---|---|---|

## Collection and immutable evidence

`tools.repair_collect` consumes the coverage run's `failures.json` or
`summary.json`. It checks the list hash against the adjacent actionable summary,
checks each episode/events/provenance file hash, resolves frozen TRAIN identity,
rejects D_probe groups, checks the configured environment seed/H/game, and
replays the recorded failures. P0 failures must have trusted demonstrations in
`--verified`; coverage's adapter identity must match `--theta0`. The supplied
verified collection is the original theta0 support, not a newly chosen set.
K counts its verified executed trajectories; instances and groups are separate.

Before constructing a teacher, the collector writes `repair_split.json`:

- Input order is the coverage order, unchanged (2..20 distinct task groups).
- **D_repair_probe = exactly two tasks**, selected by the lowest
  `sha256(canonical_json([20261029, task_id]))`, tie-broken by task ID.
  This implementation constant instantiates the design's declared seeded rule;
  it is not a CLI parameter. Probe IDs cannot be replaced after seeing labels.
- Remaining tasks retain coverage order. Each failure is passed to
  `repair_one_failure`, including the probes, until a global stop or transport
  error. Local budget/schema failures remain records and do not select new tasks.
- Near is fixed by M0b-2. Labels preserve the unchanged public reply prefix and
  rebuild reasoning plus `Action:` from the first changed decision onward.
  Far search can retain pending labels before human review; this does not approve
  a target. All nine existing pair conditions are rechecked at finalization.
  Original trusted teacher action sequences are excluded as Far targets.
- The first four **approved qualifying pairs** in the remaining frozen order
  form D_repair_train. Later pairs do not replace them based on probe results.
  Missing pairs, unrepairable probes and unknown outcomes remain explicit.

Global defaults are **5,000,000 input / 500,000 output tokens**, in addition to
the existing per-case ceilings. Before **every transport attempt**, including
429 retries, the collector reserves a conservative input bound (serialized
UTF-8 prompt bytes + 32) and the stage's output cap. Known completed usage
settles that reservation; unknown failed attempts retain their full bounds.
Cache hits retain their distinct accounting. A stop is persistent within the
run; restarting a ledger or reusing a run directory is refused. This bound is
an admission rule, not a reported tokenizer count. Provider usage that exceeds
a reservation is retained and stops further calls.

Artifacts include `collection.json` (sealed content hash), `repair_split.json`,
`e2_training_collection.json`, `cases.jsonl`, per-case `case.json` and append-only
`budget.jsonl`, `global_teacher_budget.jsonl`, `exclusions.json`, teacher raw
responses/usage ledgers, `review_requests.json`, `human_review.tsv`,
`provenance.json`, and `run_manifest.json`. The sibling `<output>_preflight`
directory retains the source failure replay evidence and its interaction ledger.
The manifest records effective configuration, input/code hashes, dependencies,
environment version/seed, theta0 identity and file hashes, tokenizer identity,
teacher requested/returned model IDs and timestamps, costs, K and zero training
exposure. Audit records are never serialized into model prompts.

`--dry-run` uses six synthetic tasks, fake teacher, fake environment and a fake
E-series-style tokenizer. It creates explicit synthetic seed artifacts and
synthetic approvals for the full collection/export path. Its export always
refuses real training. No network or model download is needed.

`--canary` reserves the same two probe IDs but acts on only the **first frozen
failure**. It executes exactly one diagnosis request when preflight/budget
admission succeeds: maximum input reservation 16,384, output cap 128, one HTTP
attempt, no 429 retry, no format retry, no proposal, no labels, no pairs.
All source hashes are checked; only this failure is replayed in canary preflight.
Admission failure makes zero requests, rather than truncating evidence to fit.
A malformed/truncated response remains `canary_failed`; it never launches a
second request. Canary and ordinary collection use separate fresh directories.

Review `human_review.tsv` and the public evidence in `review_requests.json`.
The TSV includes the corresponding `review_evidence_sha256`. A review file is
a JSON object keyed by those hashes; every decision has exactly these fields:

```json
{
  "<review evidence SHA-256>": {
    "reviewer": "human reviewer identifier",
    "no_rejected_actions": true,
    "meaningful_route": true,
    "labels_supported": true,
    "notes": "Explanation grounded in the displayed public execution and labels."
  }
}
```

Omitted decisions remain pending. Any false decision excludes that target.
No automated semantic heuristic supplies human approval. Publish a new offline
finalization without modifying the original run:

```bash
CUDA_VISIBLE_DEVICES='' PYTHONPATH=src:. "$ENV_PYTHON" -m tools.repair_collect \
  --branch "$BRANCH" --finalize "$NEW_COLLECTION_DIR/collection.json" --reviews "$REVIEWS_JSON" \
  --output "$NEW_APPROVED_DIR"
```

Finalization performs no teacher calls or environment interactions. It writes a
new collection, export, exclusions and manifest; records parent/review file
hashes; and retains original exclusions under `collection_exclusions`.
Original ledgers and TSVs remain in their immutable source run. The original
LearningEpisode ID remains stable, including its original pending status;
approval is a separate content-bound decision in each exported entry.

## E2 interchange contract (training branch needs no repair imports)

The file is `e2_training_collection.json`, with `format` equal to
`repair_e2_training_collection` and integer `schema_version: 2`.
Legacy schema 1 remains readable **only as P0_K20** (P0, adapter,
repair_tasks). Never infer P1 or K0 from a schema-1 export. Schema 2 requires
all four branch fields below, with exactly the combinations in the branch table.
Canonical JSON for every **object hash** uses sorted keys, compact separators
`,:` with no spaces, UTF-8, `ensure_ascii=False`, and no NaN/Infinity. A
`content_sha256` is SHA-256 of that entire document excluding the
`content_sha256` key. **File hashes** hash the exact bytes, including the final
newline. Do not interchange these two hash types.

Top-level fields:

| Field | Meaning |
|---|---|
| `branch` | `P0_K20`, `P1_U_mech`, or `P0_K0`; never mix these results |
| `protocol` | `P1` only for P1_U_mech; otherwise `P0` |
| `theta0_kind` | `adapter` or `base_model` |
| `seed_replay_scope` | `original_support` only for P1_U_mech; otherwise `repair_tasks` |
| `source_collection_sha256` | Exact byte hash of the adjacent finalized `collection.json` |
| `source_collection_content_sha256` | Its canonical content seal |
| `theta0` | Adapter: existing `inspect_adapter` identity plus every checkpoint file hash. Base: identity with `base_model`, `revision`, `metadata_sha256`, `weight_verification`; `files` is the same metadata hash map, covering local JSON/Jinja files, **not weight shards** |
| `tokenizer` | `id` (hash of metadata file-hash map), `files`, `chat_template_sha256` (canonical string hash) |
| `input_hashes` | Original collection input file path → byte hash, including frozen manifests and repair sources |
| `split` | Seed, rule, coverage `failure_order`, two probes and ordered `training_candidates` |
| `D_repair_train`, `D_repair_probe` | Ordered task ID lists; four approved pairs and two held-out repair-update tasks respectively |
| `K_trusted_seed_trajectories` | Original verified support size, never inferred from repair task count |
| `unique_instances`, `task_groups` | Counts for the selected repair-training tasks |
| `dry_run`, `canary`, `training_exposure` | Execution mode and exposure (zero on this branch) |
| `ready_for_training`, `training_blockers` | Ready only with four approved pairs, seed references for each task, and neither synthetic nor canary data |
| `arms` | Exactly `N` and `F`, each an ordered list in D_repair_train order |
| `seed_replay_task_ids` | Replay pool task IDs; original K20 for P1, D_repair_train for P0 |
| `seed_replay_tasks_are_repair_tasks` | Explicitly false for P1 |
| `supervision_accounting` | Initial K, theta0's seed exposure, new-task counts and per-case budgets; collection training exposure is zero |
| `original_teacher_far_policy` | `excluded_without_replay_pair_check`, including the base-model branch |

For `theta0_kind=base_model`, the training branch must construct the inherited
tsft LoRA **from scratch with identical initialization for N and F**, using the
same configured base repo/revision and metadata. Do not load an SFT adapter.
This tree contains no trainer. Local snapshot revision and metadata binding do
not certify base weight bytes, matching existing serving provenance.

Each arm entry contains `task_id`, `group_id`, `learning_episode_id`,
`repair_id`, `trajectory_id`, `source_bucket: "successful_repair"`,
`episode`, `episode_sha256` (canonical object hash), `human_review`, and
`seed_demonstrations`, the four branch fields, `design_bucket` (G for P1, R for
P0) and `seed_design_bucket: "D"`. `episode` is the public projection of the LearningEpisode
in the **existing train.dataset.episode_examples schema**, not a new trainer
serialization:

```json
{
  "schema_version": 2,
  "task_id": "train/<game>/<trial>",
  "split": "train",
  "sealed": false,
  "initial": {"visible": {
    "observation": "Exact initial harness observation",
    "admissible_commands": ["Exact public command"]
  }},
  "steps": [{
    "event_id": "<learning_episode_id>:0",
    "action_raw": "Thought: Public-prefix-supported reasoning.\nAction: exact executed command",
    "visible": {
      "observation": "Exact post-action harness observation",
      "admissible_commands": ["Exact public command"]
    }
  }]
}
```

`steps` has one entry per actual executed decision, in order. The input visible
context for decision zero is `initial.visible`; subsequent contexts come from
the preceding step. A step's `visible` is its **post-action** observation.
Command lists use the unchanged harness whitelist's sorted unique strings.
`action_raw` is the reconstructed public reply (or the unchanged original
prefix reply); its parsed action must equal the witnessed executed action.
The exporter checks this and equality with LearningEpisode.student_history.
There are no rewards, success labels, PDDL facts, audit dictionaries, diagnosis,
native input IDs, or cached token masks in `episode`. Task IDs and event IDs are
accounting fields, never extra prompt text. The normal encoder builds the
shared public messages and supervises assistant replies/native turn ends.
Tests feed this exact projection through both this tree's encoder and the
read-only encoder at **2506fa9**, for turn and episode packing.

`human_review` contains `status: "approved"`, `reviewed: true`,
`approved: true`, `evidence_sha256`, `episode_sha256`, and `decision`.
`decision` has `trajectory_id`, `episode_id` (the LearningEpisode ID), `reviewer`,
`notes`, and the three explicit boolean decisions from the review JSON. The
evidence hash binds `review_requests.json`'s public execution, labels and prefix
checks; the episode hash additionally binds the exact public training payload.
Pending/rejected targets remain in `collection.json` and do not enter `arms`.
An incomplete export has empty/short arms and `ready_for_training: false`.

Each `seed_demonstrations` item contains:

- `task_id`, `episode_id`: the trusted original executed demonstration.
- `verified_collection_path`, `verified_manifest_sha256`: selected K view and
  exact byte hash of its `manifest.json`.
- `evidence_root`, `episode_dir`: resolved largest-collection root and the
  receipt-relative directory (important for nested K views).
- `episode_sha256`: exact byte hash of `<evidence_root>/<episode_dir>/episode.json`.
- `receipt_sha256`: canonical object hash of `receipt`; `receipt` is the full
  original verified receipt, including `episode_hashes` and execution evidence.

These are evidence references, never model inputs. Paths can be remapped across
hosts, but the byte hashes/receipts must match. Resolve paths beneath the stated
root. For P0, validate through the training tree's existing verified-collection
and checked episode readers. For P1, use scoped validation as described below;
do not trust an arbitrary path or a teacher success claim.
Under `repair_tasks`, only the four D_repair_train tasks contribute seed
replay; probe and other support demonstrations receive no exposure. Under
`original_support`, each entry references the same full original K20 pool,
disjoint by task and group from **all repair tasks**, including repair probes.
Deduplicate this shared pool by `(task_id, episode_id, episode_sha256)` before
sampling; repeated references are not extra demonstrations or exposures. Both
arms carry identical seed references. Never load the parent full-TRAIN episode
pool while resolving a P1 replay reference; validate the scoped original view
and only its referenced evidence. Parent selection/receipt metadata is audit
input, not a model input.

**Required training-reader checks:** reject unknown format/version or inconsistent
branch/protocol/theta0-kind/replay-scope, schema 1 outside P0_K20, failed
content seal, source-collection mismatch, synthetic/canary/not-ready exports,
missing/duplicate/misordered tasks, train/probe overlap (including groups), any
unreviewed/unapproved target or changed episode hash, absent seed evidence,
changed theta0 files/base revision, and changed tokenizer/template. Construct
model inputs from the schema-2 whitelist above and use the existing encoder;
never pass a full arm entry or receipt to a model. Re-tokenize on the training
tree; do not import native token arrays from collection audit records. Record
all training exposure on that branch. `repair.export.require_approved` is an
executable reference guard, not a required cross-branch dependency.

## Fixed-checkpoint observation and training receipt

`tools.repair_probes` serves one observation schedule at a time:
`shared/0`, `N/{1,5,20}`, or `F/{1,5,20}`. The collection must be real and sealed.
The existing LoRA equivalence report must bind each served adapter, configured
base/revision and endpoint. P0_K0 `shared/0` instead requires the configured base
model with an empty adapter list, no merged/trained checkpoint, matching
revision/metadata hashes and endpoint; omit `--lora-check`. All nonzero
checkpoints still require LoRA equivalence and the training receipt.
Server provenance must show **BATCH_INVARIANT=1**.
Checkpoint zero must match collection theta0 hashes.

For each fixed repair probe, h_i is immediately before the first changed Near
action. A_i+ is built only from successful execution witnesses with the same
reset and every preceding original action/observation/audit transition
unchanged. Earlier-changing Far routes are excluded. A real reset and exact
original reply-prefix replay precede eight sampled turns, with seeds 0..7,
T=0.7, top_p=0.95, n=1, thinking off and output cap 1024. Request seeds use the
existing sampled student's hash of `[seed, task_id, zero_based_turn]`. Neither
repaired reasoning nor a diagnosis enters the probe prompt.

The first two seeds each get another independent reset+prefix replay and an
autonomous continuation to the original H=40. Prefix turns consume H; parser
errors use the existing feedback/turn semantics. Context overflow is a known
failure, transport/replay errors remain unknown. Failure position means the
first observed parser error after the prefix, otherwise the terminal boundary;
it is not a claimed causal diagnosis. Unknown runs have no failure position.
A_i+ is a witnessed subset, so a miss is not automatically an incorrect action.

Only shared/0 and N/F/20 run the 24 frozen D_unseen_quick tasks, greedily from
initial state through **eval.run_suite.run_suite**, saving existing per-task
records. Evaluation makes no teacher calls and writes no training examples.
Per-checkpoint `checkpoint.json` is sealed and accompanied by provenance and a
manifest. The combined JSON/TSVs report average and per-probe
`delta_m_N_minus_delta_m_F`, continuation outcomes, paired quick-eval outcomes,
and missing checkpoints/unknowns. No missing measurement becomes a zero.

For nonzero checkpoints, the training branch must produce a JSON receipt with
this contract (additional accounting fields are permitted):

```json
{
  "format": "repair_e2_training_run",
  "schema_version": 1,
  "arm": "N",
  "dry_run": false,
  "theta0": {"identity": "<copy the export's identity object>", "files": {}},
  "training_collection_sha256": "<exact e2_training_collection.json byte hash>",
  "source_collection_sha256": "<exact finalized collection.json byte hash>",
  "checkpoints": [{
    "update": 1,
    "status": "saved",
    "path": "/training/host/checkpoint/path",
    "sha256": {"adapter_config.json": "<byte hash>", "adapter_model.safetensors": "<byte hash>"}
  }]
}
```

`theta0` is the complete unchanged export object, not the illustrative abbreviated
value above. `checkpoints` includes one saved record for each fixed update
1/5/20. For P1_U_mech and P0_K0 the receipt additionally includes all four
unchanged branch fields from the export.
`sha256` maps **every file** in that checkpoint directory, including any
training-state/metadata files. The probe reader validates the actual served
adapter directory against that map, so the historical `path` can differ across
hosts. It also validates arm, export/source file hashes, all episode approvals,
and theta0. This is a receipt interface only; this branch creates no trainer.

## One-GPU stage scripts

**This pilot runs on rai, without SLURM.** The `.slurm` filenames are retained
for compatibility; invoke them with `bash`, with `HPG_CONFIG` pointing to the
rai environment file. `PROJECT_ROOT` defaults to the scripts' worktree when
SLURM variables are absent. No SLURM command or variable is required. Caller
cache exports and the rai environment's runtime/model paths are preserved.

`scripts/hpg_repair_coverage.slurm` and `hpg_repair_probes.slurm` follow this
tree's `hpg_eval_adapters.slurm`/`eval_adapters.sh`: first run the existing HF
LoRA reference, then existing adapter serving, then its HTTP equivalence check,
then the CPU environment driver. Both use one allocated GPU and a fresh dynamic
loopback port, and preserve logs on error. They use the unchanged
`harness/serve_student.py` E-series path, including its TRITON_ATTN pin; no new
model loader or attention implementation is introduced.
P0_K0 coverage and shared/0 probes instead serve the base with no LoRA flags or
equivalence check. They do not require ADAPTER, THETA0, VERIFIED or TRAIN_PYTHON.
P1 equivalence checks use only original K20 evidence; for probes, set THETA0 to
its local adapter path if the collection's historical theta0 path has moved.

Export `PROJECT_ROOT` pointing at **this worktree**, `CONFIG`, the pinned E4B
`MODEL_PATH`, and the installed `ENV_PYTHON`, `VLLM_PYTHON`, `TRAIN_PYTHON`.
Export the grid's OFF_HOME cache paths before submission: `ALFWORLD_DATA`,
`VLLM_CACHE_ROOT`, `TRITON_CACHE_DIR`, `HF_HOME`, `XDG_CACHE_HOME`,
`SED_HASH_CACHE_DIR`, plus `ALFWORLD_DATA_ROOT` for actual game files. The scripts
preserve these values and require them; they do not choose another cache root.
Use `REPAIR_OUT` for a fresh stage root. Existing roots/symlinks are refused.
