# Repair pilot M0b-2

CPU implementation of the diagnosis/proposal/label stages and E1/E2 evidence
construction. No real teacher request, environment rollout, model load, GPU,
training, commit or push was performed for this milestone. Fake executions
test software behavior; they do not establish a mechanism finding.

## Library entry points

The collector supplies an authorized **frozen training task**, its recorded
`TrajectoryRecord`, the unchanged environment factory/config, and one new
`BudgetLedger` per original failure. Task identity, environment seed and H=40
must match. Evaluation tasks are refused. The calling collector still owns
manifest authorization, recording expansion lineage and publishing artifacts;
the library does not infer split membership from a task description.

```python
from repair.driver import repair_one_failure
from repair.labels import reconstruct_labels
from repair.pairs import construct_pair
from repair.runtime import CaseSession, make_teachers

# make_teachers constructs the existing capped clients; it makes no request.
# In CPU tests, inject FakeTeacher instead.
session = CaseSession(task=task, teacher=teacher, ledger=ledger, config=config)
outcome = repair_one_failure(failure, env_factory=env_factory, session=session)
if outcome.repair.repair_status == "VERIFIED":
    labels = reconstruct_labels(
        outcome.repair, session=session, tokenizer=student_tokenizer,
        tokenizer_id=frozen_tokenizer_hash, review_path=review_tsv)
    pair = construct_pair(
        outcome, labels, session=session, env_factory=env_factory,
        tokenizer=student_tokenizer, tokenizer_id=frozen_tokenizer_hash,
        reviewer=read_reviewed_public_evidence)
```

`outcome.repair` is an M0a `RepairRecord`; `outcome.e1` contains original,
each single block, full patch and revert-and-restore rows, including unknown
measurements. Candidate evidence, hand-back results, stop reasons and costs
are separate fields. Serialize the repair with `to_json()`; the same method
is available on `DiagnosisRecord` and `LearningEpisode`.

Keep this **same session** for search and Near labels. Far has a separate
branch cost record and proposal allowance, while the one format retry,
total teacher calls/input/output/rationale caps and the 24 replay slots remain
case-shared. Recreating an already-started branch against the same ledger is
refused, so restarting cannot silently reset its budget. This milestone does
not implement automated crash recovery. Retain interrupted/unknown ledgers
for explicit reconciliation rather than creating a new failure case to retry.

## Teacher stages and budgets

`prompts.py` implements separately versioned diagnosis, joint proposal,
alternative-route proposal and prefix-label templates. Every request records
the template SHA-256 and exact message hash. Teacher inputs select task text,
public replies/actions/observations, zero-based action IDs, and permitted
outcome/config fields. They never serialize full records, audit rows, command
lists, task paths, demonstrations or another task. Prefix labels omit the
diagnosis, full failed trace, future plan and future observations.

`schemas.py` rejects extra/duplicate keys, incorrect types, invalid evidence
IDs, more than three candidates, more than four blocks, and overlong labels.
Diagnosis certainty accepts `supported`, `unknown`, or the design's literal
`supported_or_unknown`. Patch bounds/overlap are semantic rejections, passed
to a remaining proposal round rather than guessed or format-retried. A schema
failure uses the **single case-shared retry**; another schema failure stops
the case. Raw responses and rejections remain in the ledger.

`runtime.py` uses `teachers.capped.CappedTeacher`, `Teacher.generate`,
`teachers.stage.require_completed`, and the existing 429-only retry behavior.
It contains no HTTP client. `make_teachers` keeps configured model identity,
sampling and limits, with stage output caps 2048/6144/128. Before every logical
request it reserves a conservative UTF-8 input bound and the full output cap.
The existing transport reservation hook applies the same preflight before
each HTTP retry. Failed/unknown attempts retain their reservation and unknown
usage; completed attempts settle reported usage. Format and transport retries
are distinct. Cache accesses consume conservative logical slots, but cached
usage is not billed again. Every attempt, result, retry, rejection and cache
hit is recorded in the M0a ledger; the provider ledger retains transport detail.

Case provenance records effective model/environment settings, config and code
hashes, dependency versions, configured manifest/freeze hashes when present,
and authorized task/lineage metadata. Requests retain the configured alias,
returned model ID and timestamp via existing teacher metadata. Missing frozen
input files stay explicitly null; a real collector must supply its frozen
inputs and run manifest before execution.

## Search and E1

The driver measures the original once before contacting a teacher. It requests
one diagnosis and up to two rounds of three proposals. Round two receives only
actual candidate execution observations/results plus semantic patch rejection
codes. Canonical compiled actions are deduplicated. Success stops execution,
so an unexecuted suffix never improves a candidate's cost. The default
preservation tie term is zero because natural-language diagnosis is not a
registered executable predicate.

The M0a checker accepts the driver's already measured original/selected
executions and consumed counts, performs bounded whole-block reverts, and
reserves an uncached confirmation. Two-block singles are the corresponding
reverts. Three/four-block singles are separately measured within the ablation
and total caps, and any better observed success participates in selection.
Unmeasured evidence remains unknown. Existing standalone checker behavior is
unchanged when these executions are not supplied.

Optional `student_policy(history, visible_context)` performs up to three
diagnostic hand-backs. Each uses actual reset and prefix replay, checks reset
and transition consistency, then invokes the policy within the original H.
No snapshot, synthetic observation or old-state restoration is used. Failure
of the diagnostic does not remove the successful repair.

Recorded parser-feedback turns currently stop this collector with
`INVALID_PATCH` / `original_contains_parser_feedback`: they are not silently
renumbered as environment actions. The M0a executor still supports them; a
separate declared turn-to-action editing protocol is required to repair them.

## Labels and E2

Labels preserve original reply bytes and public observations before the first
modified decision, then build sequentially from the current repaired prefix.
The next request includes the preceding accepted label. Citations must precede
the current action; mentioned instance IDs must already occur in task/public
prefix. Failed grounding or incomplete budgets return **no partial episode**.
Every label, including preserved original labels, appears in the TSV with
structural checks and blank human-review columns. Natural-language support
requires review; structural checks alone do not establish it.

The `LearningEpisode` stores the full public trajectory, full-view decision IDs,
8.4 repair-mask decision IDs, checkpoint/source metadata, and label protocol.
Student history retains the harness's explicit public visible fields, including
its ordinary admissible commands; the teacher label prompts omit command
lists. With an injected student chat tokenizer, the existing
`train.dataset.episode_examples` encoder supplies native packed IDs/masks and
supervised counts including turn ends. No tokenizer is downloaded or loaded.
Without it, text-segment masks and whitespace counts are inspection artifacts;
strict E2 filtering rejects them until native counts are available. All
episodes initially have `pending_human_review` status. Action-only labeling is
an explicit option that must match across both arms.

Far defaults to **one extra proposal request**, up to three candidates.
`proposal_rounds=2` exposes the design's maximum of 2×3 for that branch;
it is not an automatic unlimited search. Candidates execute through M0a.
Known route/coverage/length/distance failures are rejected before labeling;
remaining successful candidates receive the same prefix-label protocol.
All nine E2 conditions are checked, with every exclusion retained.

Object instances, goal destinations and operation signatures come only from
executed ALFWorld action syntax and public observations. Unrecognized or
ambiguous coverage is rejected as unknown. An injected reviewed-evidence reader
must explicitly certify public action acceptance, meaningful route quality and
label support, supplying reviewer/notes bound to trajectory and label IDs.
Without that review the result is `PAIR_NOT_FOUND`, preserving E1. Observation
patterns can identify rejection, but an admissibility audit flag is never used
as proof that an action was accepted.

Near is always the original selected best observed repair. Bad Near quality
excludes the task without replacing Near. Eligible Far candidates are ordered
by action-length ratio closeness to one, then absolute supervised-token
difference, then patch ID. `first_pairs` takes the first four successes in the
caller-supplied frozen task order for both arms.
