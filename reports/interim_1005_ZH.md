## 2. 剂量曲线（见附图 seedsft_sweep.png）

- **约 10 万监督 token 以内，三个 K 的曲线几乎重合**：都在 3–6 万 token 处跌破 base（最低约 33%），之后回升。也就是说，早期崩溃由训练暴露量决定，与 K 无关。
- 10 万 token 以后 K 开始拉开：K=20 一路涨到约 80%；K=5 和 K=10 在 40 万 token 时约 60–67%，种子集之间差异很大（K=5：72 / 101 / 81；K=10 s2 在 20 万 token 时就到了 104）。
- 因此，"多少经验才够"必须在剂量足够之后才能回答。baseline 的官方配方大多是在几千条轨迹上调出来的，换到 K=5–20 时剂量几乎都落在低谷（Kang 63 就是例子），所以每个 baseline 都会同时报告官方剂量和剂量对齐两个版本。

## 3. 失败机制分析（学生：K=20 s0 训 20 遍，68.6%；gap 集为"教师成功、学生失败"的 24 局）

**3.1 失败发生在哪里。** 从学生每个前缀让教师接手，记录教师还需几步才能成功（D）。全部 24 局都找到了"离成功最近的状态" t\*：
- 中位数离成功只差约 5 步，而当时平均还剩约 25 步可用。
- "在灯下看"类 4 局中有 3 局曾**只差 1 步**（例如把放下的碗重新拿起），之后十几步都在打转。
- 约 5 局从头到尾没有任何进展（t\* ≤ 1）。

**3.2 在 t\* 处的干预**（每种干预只改那一步的输入，之后学生自己走；贪心成功且 4 次采样中至少 3 次成功才算"救回"；I0 为配对对照）：

| 干预 | 救回 | 95% 区间 |
|---|---|---|
| I0 不改动（对照） | 0/24 | 0–14% |
| I1 复述已经看到的事实 | 3/24 | 4–31% |
| I2 合法地重新观察一次 | 2/24 | 2–26% |
| **I3 教师建议（只给计划，不给动作）** | **11/24** | 28–65% |
| I4 教师直接给下一步动作（上限参照） | 9/24 | 21–57% |
| **I5 把一条同类种子轨迹放进上下文** | **8/24** | 18–53% |

**3.3 按预注册的判定表**（以对 I0 的配对超出为准）：
- 只有"更明确的决策信息"（I3/I2）能救回，即**机制 2**：7 局。
- 只有"经验/已知信息"（I5/I1）能救回，即**机制 1**：4 局（要确认为机制 1，还需证明种子里确实演示过所缺的那一步，这部分检查尚未实现）。
- 两者都能救回：4 局。
- 都不能救回：9 局，其中 1 局只有 I4 能救。

**3.4 按任务类型看，初步出现分工：**
- **加热类**偏向机制 1：6 局中有 3 局只有"放入种子示例"能救回。加热的步骤（拿起物体 → 用微波炉加热）就在种子里，学生训练后却用不出来。
- **"在灯下看"和"两个物体"类**偏向机制 2：差一步卡住时，重新观察或一句建议就能救回，放种子示例反而不行。
- **冷却类和离终点很远的失败**大多救不回：离成功还有 7–20 步，单步干预不够。

**3.5 需要谨慎的地方：** 只有一个学生、一个种子集、24 局，区间都很宽；机制 1 的"种子覆盖"和知识探针（方案第 4 节）还没做；I3 的建议文本可能隐含了动作，所以 I3 和 I4 要一起看。下一步会在 K=5/K=10 的高剂量学生上重复（gap 更大，样本更多），并补上覆盖检查和探针。

## 4. 方法学上的发现（会写进论文附录）

1. **vLLM 贪心解码在并发下不可复现**：同一 base 模型在两个 server 上跑，只有 8/140 条轨迹完全一致，12 局结果翻转。batch-invariant 模式在同一 server 配置下能做到逐局一致（40/40），但 LoRA 槽位数不同时仍有 5% 的结果差异（70/140 条轨迹一致，7 局翻转）。因此最终评测采用"一个 server 只服务一个模型"的固定配置。
2. **LoRA 部署精度**：训练用 fp32 LoRA，vLLM 只支持 bf16/fp16，剂量越高差异越明显；合并到 bf16 权重的误差反而更大（logit 平均差 1.1–1.4）。所有模型统一用不合并的 LoRA 部署，等价性检查的结果逐个报告。
3. **按整局打包训练时的格式陷阱**：Gemma 4 生成时有一个空的 thought 标记，而历史轮次里没有。高学习率的 baseline（Kang，lr 2e-4）因此在第 1 步全部格式出错。baseline 已统一改为逐轮、使用评测时的确切前缀训练。
4. **机制分析的定义修订**：ALFWorld 里几乎所有状态都能挽回，所以"首个不可挽回错误"总是落在步数用完的那一刻；已改为在"离成功最近的状态"施加干预（预注册方案修订 3，在任何干预结果出来之前完成）。
