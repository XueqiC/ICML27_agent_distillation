# 11-07 阶段总结的详细说明：数据侧（v0）和直接改权重（P0 / P1）具体是怎么做的

写于 2026-11-15（CST）。11-07 的总结只列了结论和数字，这份把两条路线从头到尾讲一遍：每一步的输入、做法、输出、K20 上的实际数字，并各给一个真实例子。数字都来自 `notes/exp_log.md`、prereg 文档和原始记录（rai 上的 `ICML27_v0_runs/v0_k20_r1`，rsi 上的 `reports/p1_runs`），没有新跑实验。

## 0. 先说结论，以及 11-07 没讲清楚的两点

1. **数据侧 v0**：让学生去做 harness 合成的新题，失败的地方请 teacher 做最小修改并在真实环境里验证，把验证成功的轨迹加进训练集，再从 θ₀ 继续训练。只做了一轮。dev140 上比起点 θ₀ 高 21–24 题（/140），和 AD 基本持平。
2. **直接改权重 P0 / P1**：不造新数据，让 teacher 用白盒工具读学生的内部状态，直接改学生的权重。局部的失败状态能修好一部分，但传不到整题，dev140 几乎不动；用同样的数据直接做 SFT 更好。
3. **11-07 没讲清楚的第一点（重要）**：P1 里 teacher 实际提交的"手术"，五个类别会话和设置 B 的会话全部是同一种做法——用梯度归因挑 2–3 个模块，在这些模块上对诊断配对做 40–100 步的小 LoRA 微调（整合会话只是把五个增量各乘 0.25 叠加）。它没有用 logit lens、注意力、激活修补这些读机制的工具，写下的"机制假设"也只是泛泛一句话。所以 P1 的结论应该读作：**这一版 teacher agent 的改权重不如简单做法**。"teacher 读懂机制后做精确手术"这个想法本身，实际上没有被测到（细节见 §3.6）。
4. **没讲清楚的第二点**：v0 的两个 variant 里，"D-data 的一致性加权"在 K20 上几乎是空的（134 个修复里 123 个被分到同一组），"D-param 只训 25% 张量"是有害的。真正起作用的是**合成题 + teacher 修复产生的数据本身**，其中 G2（换目标）贡献最大。

## 1. 共同设定

- **任务**：ALFWorld 文本环境。一个任务 x 包含指令和初始观察。第 t 步学生输出 y_t =（Thought_t，Action_t），环境返回观察 o_t。历史 h_t =（x, y_1, o_1, …, y_{t−1}, o_{t−1}）。每题最多 40 步（H = 40）。
- **学生**：Gemma-4-E4B-it + LoRA。**teacher**：黑盒 gpt-6-luna，只能通过 API 调用。
- **harness**：我们自己的执行框架。它把环境包起来，负责执行动作、记录每一步是否被环境拒绝（inadmissible）、重放轨迹、合成新题。
- **训练数据的规则**：只有 K 条 teacher 的成功轨迹（K = 10 / 20 / 30），和 baseline 相同。额外的监督只能来自 harness 合成的题、学生自己的作答、teacher 的查询。dev140 只用于最终评测，不参与任何选择。
- **起点 θ₀**：主网格里的"轨迹 SFT"seed 0，也就是直接在 K 条轨迹上做 LoRA 微调得到的模型。K20 的 θ₀ 在 dev140 上是 78/140。
- **评测**：dev140 = 140 个留出任务，greedy 解码，hpg B200，和 baseline 用同一套脚本。单位都是"做对的题数 /140"。同一个模型测两次可能差 0–7 题，所以几题以内的差别不下结论。
- **比较对象（K20，三个种子）**：轨迹 SFT 78 / 78 / 90，AD 104 / 95 / 97，SmartAD 84 / 90 / 98，SAD 52；不训练的原始模型 43，teacher 自己 114。

## 2. 数据侧 v0：一轮是怎么做的

### 2.0 为什么要合成题

θ₀ 在它自己的 K20 训练题上成功率是 100%（每题 1 次 greedy + 3 次采样）。也就是说，原题上没有错误可以拿来修。**错误必须靠新题暴露出来**，所以整个流程的入口是合成题。

一轮的流程：

```
K 条示范 ──SFT──► θ₀
                  │
   S 合成题 ──► A 学生作答 ──► B teacher 评价 + 最小修改 + 真实执行验证
                                   │
                                   ▼
                      D 梯度分析（两个 variant）──► C 扩题（再走一遍 A、B）
                                   │
                                   ▼
                      E 混合训练（从 θ₀ 继续）──► θ₁ ──► F dev140
```

### 2.1 S：harness 合成练习题（不调用 teacher）

从 K20 的 20 个任务**自己的游戏文件**出发改出新题，四类生成器：

| 生成器 | 做法 | 档位 |
|---|---|---|
| G1 换位置 | 同一场景、同一目标，把目标物体挪到另一个放得下它的容器里 | 很近 |
| G3 出错状态 | 在原示范中途真实执行一个受控错误（被拒动作、拿错物体、放错位置、一段无效搜索），让学生从那里接着做 | 很近 |
| G2 换目标 | 同一场景和初始状态，换成别的物体、容器（同任务类型 = 中等），或换成另一种任务类型（= 远）。目标的 PDDL 写法照抄真实训练游戏 | 中等 / 远 |
| G5 组合改动 | 换任务类型 + 换位置 + 加入同类干扰物 | 很远 |

每个合成题必须通过检查才保留：能加载；任务文本与新目标一致；**有可解见证**（用 Fast Downward 规划器在 harness 里真实执行成功，见证只证明可解，不进训练文本）；reset 两次结果相同；和 dev140、valid_unseen 等留出集**不重名**（任务类型、物体、容器、场景都相同就算重名）。

K20 实际结果：

- 训练用合成题 **206 个**（很近 66 / 中等 80 / 远 40 / 很远 20），另有 **71 个留出合成题**从不训练，只用来诊断。
- 被拒的候选：和留出集重名 879 个、初始状态已经完成 120 个、有歧义 35 个、超时 6 个。
- 计划的比例是 50 / 30 / 15 / 5%，实际是 32 / 39 / 19 / 10%：有 9 个 K20 任务的"任务组"恰好也出现在留出集里，G1 不改任务组名，所以这些任务的"很近"档候选全被排除。按 prereg 不补题。

### 2.2 A：学生作答

θ₀ 在每个合成题上做 4 次：1 次 greedy + 3 次采样（T = 0.7，top_p = 0.95）。

- 206 题 × 4 = 824 次作答，成功率 72.9%。
- 按档位：G1 88%，G3 78%，G2 中等 67%，G2 远 70%，G5 72%。
- 206 题里有 **85 题至少失败一次**，其中 31 题四次全失败。
- 学生自己做成功的轨迹原样保留（后面进 S 桶），不改写成 teacher 的风格。

### 2.3 B：teacher 整体评价 → 最小修改 → harness 真实验证

每个合成题最多取 2 条失败作答，共 **146 条**。对每一条：

1. **harness 标注**：逐步写出这一步是否被环境拒绝、前提条件是否满足、看过哪些容器、是否在重复。
2. **teacher 读完整条轨迹**，输出结构化评价：
   - 学生的计划（子目标序列）；
   - 可以保留的选择（和 teacher 的做法不同但能完成任务的，不算错）；
   - 走不通的位置和原因（breaking points，带类别）；
   - **最小修改**：最多 2 个修改块，每块是具体的环境动作（替换 / 插入 / 删除某几步）。
3. **harness 闭环验证**：重放到修改处 → 执行修改 → **先重放学生原来的后续动作**；不成功，再把控制权交还给学生 θ₀ 从修改后的状态接着做；还失败，就把新轨迹交回 teacher 再评价，最多 3 轮。**只有在真实环境里最终成功才算修复。**

K20 实际结果：

- 146 条失败里 **134 条修复成功（91.8%）**。
- 其中 94 条是"修改 + 学生原来的后续动作"直接成功，40 条需要交还学生接着做。
- 107 条一轮就成功，22 条用了两轮，5 条用了三轮。
- 最终成功轨迹里的动作来源：学生原有的 69%，交还后学生新做的 14%，teacher 修改块的 17%（平均每个修复 4.6 个动作）。也就是说，**训练目标的大部分仍是学生自己的动作**，teacher 只改了走不通的地方。
- teacher 用量：4.72M 输入 / 0.475M 输出 token。

**一个真实例子**（G2，"远"档）：

- 父任务（K20 原题）：清洗一把 butterknife 放进 drawer。
- 合成题：同一个厨房，目标改成 `put a cool lettuce in garbagecan`。
- 学生 θ₀ 的 greedy 作答：`go to fridge 1` → `open fridge 1` → `take lettuce 1 from fridge 1` → `go to garbagecan 1` → `move lettuce 1 to garbagecan 1`。它没有执行"冷却"，任务没完成，之后在 look / examine / 拿起又放下之间循环，直到 40 步用完。
- teacher 的评价：第 3 步是 `missing_precondition`——拿到生菜后应该先 `cool lettuce 1 with fridge 1`，学生把"生菜原来在冰箱里"当成了"已经是冷的"。
- teacher 的最小修改：**在第 3 步前插入一个动作** `cool lettuce 1 with fridge 1`。
- harness 验证：重放学生的前 3 步 → 执行插入的动作 → 重放学生原来的后两步（去垃圾桶、放下）→ 任务成功，共 6 步。
- 这条 6 步的成功轨迹成为一个"修复 episode"：5 步是学生自己的，1 步来自 teacher。这次 teacher 调用用了 20,088 输入 / 1,921 输出 token。

### 2.4 怎么变成训练样本

- **一行训练样本 = 一个决策**：输入是到第 t 步为止的完整历史 h_t，监督目标是这一步的 y_t（Thought + Action）。
- 修复 episode 监督整条验证成功的轨迹，但**跳过被环境拒绝的动作和重复的被拒动作**。
- teacher 的修改块只有动作，没有 Thought。修改处的 Thought 由一个"理由标签器"补写，要求和前文一致。
- 四个数据桶：

| 桶 | 内容 | K20 第一轮 |
|---|---|---|
| R | 2.3 的修复 episode | 134 个 episode / 2,915 行（其中修改处的决策 495 行） |
| S | 学生在合成题上自己做成功的轨迹，每题最多 1 条 | 175 个 episode / 2,616 行 |
| D | K20 的 20 条原示范 | 20 行（每行是一整条示范） |
| G | 扩题得到的修复和学生成功（见 2.6） | 见下 |

### 2.5 D：梯度分析的两个 variant

在 θ₀ 上，对每个修复 episode i 计算 LoRA 参数的梯度 g_i。loss 和训练相同，但只算**修改处的决策**；关闭 dropout，不更新参数。然后有两种用法，对应两个 variant：

**D-data（跨错题比较，用来分配数据）**
- 把每个 g_i 用 CountSketch 压到 2,048 维，按余弦距离做 k-medoids 聚类（k ≤ 6）。
- 组一致性 = 组内平均余弦相似度 × 组大小。
- 用途：一致性高的组分到更多扩题名额；训练时这些组的 episode 在 R、G 桶内被抽中的概率更大。训练**全部** LoRA 张量。
- K20 实际结果：5 个组，但 **123/134 落在同一个大组**（平均余弦 0.184），其余 4 组各 2–4 个。分组几乎退化，所以 D-data 的分配和加权基本等于均匀。原因是原始余弦被一个所有错题共有的分量主导。K30 上分组好一些（50 / 118 / 2 / 5 / 2 / 36）。

**D-param（跨参数比较，用来选参数）**
- 对每个 LoRA 张量计算信噪比：‖mean_i g_i‖ / sqrt(mean_i ‖g_i − mean g‖²)。意思是，各错题在这个张量上的梯度方向是否一致。
- 取信噪比最高的 25% 张量，只训练它们，其余冻结。扩题按 teacher 给的错误类别平均分配。
- K20 实际结果：516 个 LoRA 张量里选了 129 个，全部在第 20–41 层（mlp.down 35、mlp.up 31、attn.o 27、mlp.gate 24、attn.q 7、attn.v 5）；可训练参数 39.0M（全部是 139.5M）。

### 2.6 C：扩题

两个 variant 各自再合成 85 个新题（数量 = 2.2 里至少失败一次的题数），仍然只从 K20 原任务出发，同样经过 A 和 B：

| | 新题怎么分配 | 作答成功率 | 修复成功 | G 桶 | 数据集合计 |
|---|---|---|---|---|---|
| D-data | 按组一致性 | 48% | 107/112 | 107 修复 + 59 学生成功，3,221 行 | **8,772 行** |
| D-param | 按错误类别均分 | 49% | 104/108 | 104 修复 + 58 学生成功，2,857 行 | **8,408 行** |

扩题上学生的成功率（约 48%）明显低于第一批（73%），说明扩题确实集中在学生不会的地方。

### 2.7 E：训练

- 从 θ₀ 继续训练，LoRA 配置沿用 θ₀（r 64、alpha 128、dropout 0.05、相同 target modules），AdamW，batch 16。
- **抽样**：每个样本先按概率 R 0.50 / G 0.25 / S 0.15 / D 0.10 选桶，再在桶内选一个 episode（D-data 按组一致性加权，其余均匀），再在 episode 内均匀选一行。
- **loss**：每行是该决策目标 token 上的平均交叉熵，batch 的 loss 是 16 行的平均。权重只影响抽样，不乘在 loss 上。
- **训练量**：对全部决策行过 4 遍，更新数 = ⌈4 × 行数 / 16⌉。D-data 是 2,193 次更新（2×B200，约 4 小时），D-param 是 2,102 次。不做 checkpoint 选择，直接用最后一个。

K20 一共训了四臂，后两臂是为了把 variant 里的两个因素拆开：

| 臂 | 数据 | episode 权重 | 训练的张量 |
|---|---|---|---|
| D-data | D-data 的 8,772 行 | 按组一致性 | 全部 |
| uniform（对照 A） | 同上 | 均匀 | 全部 |
| D-param | D-param 的 8,408 行 | 均匀 | 信噪比前 25%（129 个） |
| Dparam-full（对照 B） | 同上 | 均匀 | 全部 |

### 2.8 结果

dev140（做对的题数 /140，hpg B200）：

| K | θ₀ | AD（三种子） | D-data | uniform | D-param | Dparam-full |
|---|---:|---|---:|---:|---:|---:|
| K10 | 72 | 85 / 83 / 83 | 90 | 86 | 79 | **93** |
| K20 | 78 | 104 / 95 / 97 | 97 | **100** | 85 | 97 |
| K30 | 86 | 112 / 104 / 110 | 未完成 | 未完成 | 未完成 | **110** |

读法：

- **数据有用**：只要训全部张量，四臂里有三臂在 K10、K20 上都比 θ₀ 高 14–22 题。
- **只训 25% 张量有害**：D-param 在 K10、K20 上都是最差的（79、85）；同样的数据改成训全部张量（Dparam-full）就回到 93、97。所以问题出在参数限制，不在数据的分配方式。
- **一致性加权看不出作用**：K20 上 D-data 97 对 uniform 100，K10 上 90 对 86，都在噪声范围内；而且 K20 的分组本来就退化了，这个比较的力度有限。
- **和 AD 的关系**：v0 最好的一臂 ≥ AD 三种子均值（K10 93 对 83.7，K20 100 对 98.7，K30 110 对 108.7），但 v0 只有一个种子，K20 / K30 上比 AD seed 0 低 4 / 2 题。目前只能说"持平"。

K20 生成器消融（以 uniform 为基础，固定 2,193 次更新，每次去掉一类生成器的全部 episode）：

| 臂 | 剩余行数 | dev140 |
|---|---:|---:|
| 全部数据 | 8,772 | 100 |
| 去掉 G1 | 8,067 | 99 |
| 去掉 G3 | 7,838 | 93 |
| 去掉 G2 | 2,491 | 80 |
| 随机保留 28%（与去掉 G2 同样多） | 2,215 | 90 |
| θ₀ | — | 78 |

- G2（换目标）占非 D 行的 72%。去掉它几乎退回 θ₀；同样数据量的随机子集还有 90。所以 **G2 的内容本身重要**，不只是量大。
- 数据量也有作用（随机 28% 掉了 10 题）。G1 基本可以去掉。G5 的消融没跑完。

71 个留出合成题上（greedy 成功率）：θ₀ 69.0% → D-data 87.3%，uniform 80.3%，D-param 80.3%。训练后的学生在同分布的新合成题上确实变好了，但留出题的排序和 dev140 不一致（K20 上 uniform 在 dev140 最好，在留出题上不是）。71 题太少，不能用来在各臂之间做选择。

### 2.9 v0 还没做的

- **只做了第一轮。** prereg 里设计的是最多 3 轮：每轮先在新的留出合成题上测各档失败率，失败率高且修得好的档多出题，某档失败率的 95% 上界 < 5% 就停。第一轮后没有任何一档达到停止条件（D-data 训练后，"中等 / 远 / 很远"档仍有 20–30% 的留出题至少失败一次）。
- 只有 seed 0；K30 的三臂和 G5 消融没跑完。
- D-data 的分组需要先去掉公共分量再聚类，否则加权是空的。

## 3. 直接改权重：P0 → P1

### 3.0 想法

teacher 是黑盒，但学生是白盒。能不能让 teacher 读学生的内部计算，找到出错的位置，直接改权重，而不是靠造数据再训练？参照的是 *Sparks of Weight-Space Programming* 那篇 blog（LLM 自己读写小模型的权重）。

### 3.1 单位："配对"

全部数据来自 v0 K20 第一轮的修复记录（§2.3），不造新数据。

- 一个**配对** =（状态 s，失败动作 a_f，修复动作 a_r）：取一条失败轨迹和它验证成功的修复轨迹，找到两者第一个分叉的步 t*。s 是第 t* 步决策前的完整上下文，a_f 是学生原来的动作，a_r 是修复轨迹里 teacher 修改块给出的动作。
- 按这个定义，§2.3 的例子对应的配对是：s = 刚从冰箱拿到生菜，a_f = `go to garbagecan 1`，a_r = `cool lettuce 1 with fridge 1`。
- 134 个修复里可用的是 **113 个配对**（74 个任务实例），按 teacher 标的类别分五类：goal_misread 27、missing_precondition 37、refused_action 19、search_incomplete_or_loop 12、wrong_object_or_target 18。
- 配对按任务实例分成"诊断集"（teacher 能看、能用）和"测试集"（teacher 永远看不到）。

### 3.2 teacher 手里的工具和可以做的编辑

teacher（gpt-6-luna）以 agent 的方式工作：每一轮输出若干工具调用，我们在 GPU 上对学生执行，把结果以文本返回，直到它提交。

**读的工具**（作用在某个配对的决策点上）：
1. 动作打分：各候选动作的 log-prob；
2. 逐层 logit lens：每层残差上 a_r 与 a_f 的 log-prob 差；
3. 注意力汇总：决策位置对任务目标、最近观测、历史各步的注意力；
4. 上下文反事实：改写状态后再看 1–3；
5. 激活修补：把一次运行的残差换成另一次的，看动作打分怎么变；
6. 方向工具：两组（状态, 动作）的激活均值之差作为方向，看它在各层的投影；
7. harness rollout：从 s 起让（可带编辑的）学生 greedy 跑到结束，看是否成功；
8. 梯度归因（P1 新增）：log p(a_r) − log p(a_f) 对每层每个模块权重的梯度范数排序；
9. 神经元归因（P1 新增）：MLP 中间神经元的激活 × 梯度。

**改的方式**（P1；可以组合）：
- 去方向：W ← W − α U Uᵀ W（P0 只允许这一种，且只能秩一）；
- 加性秩一：W ← W + α a bᵀ；
- 神经元缩放；
- 局部微调：teacher 自选模块、配对、学习率、步数（≤ 200），在这些模块上训练一个 LoRA（秩 ≤ 16），loss = −log p(a_r | s)。

### 3.3 P0（限制很严的第一版）

- 诊断 23 对 / 测试 90 对。每个类别 60 次工具调用、10 次 rollout，只允许秩一去方向。
- 结果（90 个测试配对，从 s 起 rollout 的成功率）：不改 22.2%，teacher 编辑 28.9%，随机方向 20.9%，**固定规则方向 31.1%**（直接取诊断集上"失败激活 − 修复激活"的均值）。
- teacher 的编辑没有胜过一条不用 teacher 的固定规则。P1 就是把 P0 的限制都放开再测一次。

### 3.4 P1 设置 A：接在 SFT 之后

**起点**：θ₀（K20 轨迹 SFT seed 0），LoRA 合并进权重。诊断 55 对 / 测试 58 对，任务实例不重叠。

**会话**：五个类别各开一个会话（预算：300 次工具调用、25 个候选编辑），再开一个整合会话把五份提交合成一个最终的"部署编辑"。

**一条中途加的规则**：第一个会话只用了 33/300 次工具调用、2 次 rollout 就提交了。为了不让"teacher 什么时候想停"决定结果，之后规定：teacher 提交时，系统自动把这个编辑在**全部**诊断配对上做真实 rollout（改前、改后各一次），把逐配对的对照表返回给 teacher，teacher 确认或修改后才冻结。

**teacher 实际做了什么**（来自会话记录）：

| 会话 | 诊断配对 | 工具调用（上限 300） | 提交的编辑 | 诊断集上 rollout 成功（改前 → 改后） |
|---|---:|---:|---|---|
| goal_misread | 13 | 29 | LoRA 秩 8，在 41 层 q_proj、22 层 down_proj、23 层 v_proj；lr 3e-5，100 步 | 2/13 → 3/13 |
| missing_precondition | 18 | 30 | LoRA 秩 4，在 17 层 o_proj、22 层 down_proj、41 层 q_proj；lr 1e-4，80 步 | 4/18 → 7/18 |
| refused_action | 9 | 31 | LoRA 秩 4，在 10 层 down_proj、11 层 o_proj；lr 1e-4，40 步 | 0/9 → 1/9 |
| search_incomplete_or_loop | 6 | 29 | LoRA 秩 4，在 22 层 down_proj、17 层 o_proj、41 层 q_proj；lr 1e-4，50 步 | 1/6 → 2/6 |
| wrong_object_or_target | 9 | 20 | LoRA 秩 4，在 17 层 o_proj、20 层 down_proj、22 层 down_proj；lr 1e-4，80 步 | 1/9 → 3/9 |
| 整合 | 55 | 0 | 五个增量各乘 0.25 后叠加 | 8/55 → 11/55 |

五个类别的会话加起来共 139 次工具调用：apply_edit（试用某个编辑）68 次、rollout 39 次、local_finetune 9 次、action_scores 9 次、gradient_attribution 7 次、direction 4 次、neuron_attribution 3 次。**logit lens、注意力汇总、上下文反事实、激活修补一次都没用。**

**对照条件**（都作用在同一个合并后的 θ₀ 上，只用诊断集）：

| 条件 | 内容 |
|---|---|
| E0 | 不改 |
| E1 | teacher 手术（整合会话的部署编辑） |
| E2 | 随机对照：和 E1 相同的层、模块、秩，换成同样大小（Frobenius 范数相同）的随机增量；5 个种子 |
| E3 | 固定规则：每个类别取诊断集上 h(s, a_f) − h(s, a_r) 的均值作为方向，在第 20–41 层 down_proj 上去方向 |
| E4 | 用**同样的数据**直接做 SFT：55 个诊断配对所在的修复 episode + K20 原示范，从 θ₀ 继续训，全部 LoRA 张量，295 次更新 |
| E5 | 不经 teacher 的自动定位：按梯度信噪比取前 25% 张量，在上面训 LoRA（秩 16），学习率和步数在诊断集上选 |

**四个指标**：
- M1：58 个测试配对，从失败状态 s 起 greedy rollout 的成功率（局部修复有没有推广到没见过的同类失败）；
- M2：71 个合成留出题、20 个 K20 原题，从头做的整题成功率；
- M3 附带伤害：200 个学生原本做对的决策里，greedy 动作被改变的比例；
- M4：dev140。

**结果**（rsi 上评测）：

| 条件 | M1 | M2 合成题 | M3 附带伤害 | dev140（两次均值） |
|---|---:|---:|---:|---:|
| E0 不改 | 22.4% | 49/71 | 0% | 77.0 |
| **E1 teacher 手术** | **37.9%** | 50/71 | 8.0% | 80.0 |
| E2 随机 ×5 | 18.6% | 46/71 | 2.2% | 77.9 |
| E3 固定规则 | 27.6% | 47/71 | 9.0% | 77.0 |
| E4 同数据 SFT | 50.0% | 51/71 | 15.0% | **82.0** |
| E5 自动定位 LoRA | 27.6% | 45/71 | 9.0% | 72.5 |

- **局部有效**：在没见过的同类失败状态上，E1 比不改、随机、固定规则、自动定位都高 10–19 个百分点。
- **传不到整题**：dev140 只多 3 题，在噪声范围内；合成题 49 → 50。
- **同样的数据直接 SFT 更好**：E4 在 M1、dev140、合成题上都是最好的，代价是附带伤害最大（15%）。
- 按 prereg 判定：四条判据只满足 M1 一条，结论是"在现有数据上，teacher 定位改权重没有优于简单做法"。

### 3.5 P1 设置 B：取代 SFT

问题换成：拿 baseline 的 20 条轨迹，**不做 SFT**，从原始 Gemma-4-E4B-it 出发，只靠 teacher 改权重，能不能达到轨迹 SFT 的水平？

- **配对怎么来**：对 20 条轨迹的每一步（共 315 步），给原始模型同样的历史，看它 greedy 会选什么动作。和轨迹动作不同的有 **90 步**，每一步构成一个配对（a_f = 模型的选择，a_r = 轨迹里的动作）。其余 225 个一致的步作为附带伤害的抽样池。
- **会话**：一个全局会话，90 个配对全部给 teacher（预算 500 次工具调用、40 个候选编辑）。
- **teacher 实际做的**：5 轮对话，6 次工具调用——1 次梯度归因，1 次局部微调，4 次 apply_edit。提交的编辑是一个秩 4 的 LoRA，位置是梯度排名最高的三个模块（22 层 down_proj、23 层 v_proj、41 层 q_proj），只用 90 个配对里的 28 个训了 60 步（lr 1e-4），改动 3,932 万个参数（占 0.5%）。在 90 个配对上验证：改前 26/90 成功，改后 27/90。
- **对照**：B0 原始模型；B2 同结构随机编辑 ×5；B3 固定规则方向；B5 自动定位 LoRA。

结果（dev140 两次均值）：

| 条件 | dev140 | 合成题 | K20 原题 | 附带伤害 |
|---|---:|---:|---:|---:|
| B0 原始模型 | 40.5 | 34/71 | 9/20 | 0% |
| **B1 teacher 手术** | **45.5** | 35/71 | 9/20 | 1.0% |
| B2 随机 ×5 | 41.7 | 30–37/71 | 8–10/20 | 0% |
| B3 固定规则 | 39.0 | 32/71 | 9/20 | 1.5% |
| B5 自动定位 LoRA | 39.0 | 25/71 | 11/20 | 38.5% |
| 参照：轨迹 SFT seed 0 | 77.0 | | | |

- B1 比原始模型多 5 题，比随机编辑多约 4 题，离轨迹 SFT 差 31.5 题。**"P1 能取代 SFT"不成立。**
- 连它用来诊断的那 20 个训练题，整题做对的数目都没变（9/20）。

### 3.6 这个结论到底说明了什么

我当时把 P1 概括成"teacher 直接改权重不成立"，这个说法太宽了。准确的说法是：

- **测到的**：gpt-6-luna 在这套工具和提示下，每个会话都收敛到同一个策略——看一眼梯度排名，挑 2–3 个模块，做一个很小的 LoRA 微调，然后调系数。它提交的"机制假设"都是这样的句子："A low-strength supervised update on shared decision representations favors admissible prerequisite actions…"。这不是机制诊断。
- **所以 E1 和 E5 的差别**只是"teacher 挑 2–3 个模块、秩 4–8"对"自动挑前 25% 张量、秩 16"。两者本质上是同一类方法，而 E4（不限制位置、用整条修复轨迹训练）比它们都好。这和 v0 里"只训 25% 张量有害"是同一个现象：**在这个任务上，把更新限制在少数位置没有好处。**
- **没测到的**：teacher 真的用读机制的工具定位出一个可解释的方向或回路，再做精确编辑。P0 里它被限制只能这样做（秩一去方向），结果不如固定规则；P1 里放开以后，它自己选择了不这样做。
- 另一个结构性的原因：配对只监督**一步**（−log p(a_r | s)），而整题成功需要连续几十步都对。M1 从 22% 升到 38%、dev140 不动，说的就是这件事。E4 之所以更好，是因为它监督的是整条修复轨迹。

## 4. 两条路线放在一起

| | 数据侧 v0 | 改权重 P1 |
|---|---|---|
| 新增监督 | 合成题 291 个，teacher 修复约 240 条，学生自己的成功约 230 条；共 8,772 个决策行 | 不新增；只用 55 个（设置 A）或 90 个（设置 B）单步配对 |
| teacher 的角色 | 读整条轨迹，给最小修改；由真实执行验证 | 读梯度排名，选模块做小微调 |
| 参数更新 | 全部 LoRA 张量，约 2,200 次更新 | 2–3 个模块，40–100 步 |
| dev140（K20，起点 78） | 97–100 | 80（设置 A）；从原始模型出发 45.5（设置 B） |
| 在没见过的同类失败上 | 留出合成题 69% → 80–87% | 失败状态 22% → 38% |

两边都指向同一件事：**有效的是"更多、经过真实验证的整条轨迹"**，而不是"更精确地选择改哪里"。v0 里的 D-param、P1 里的 E1 / E5 / B1 / B5 都是在"选位置"上做文章，都没有收益。

## 5. 没做完的和我的建议（等你定）

1. **K30 三臂重训 + G5 消融**：prereg 里已有，命令在 11-07 总结 §6。每臂 2 张 B200 约 7 小时。要跑的话需要先把约 270 GiB 的权重从 /orange 搬回 /blue。
2. **v0 第二轮**：框架设计的是多轮，现在只有一轮。第二轮才能回答"继续出题、继续修，dev140 还涨不涨"。我认为这是最值得做的下一步。
3. **种子**：v0 只有 seed 0，而 AD 有三个种子。要说"持平"或"超过"，至少 K20 需要再补两个种子。
4. **D-data 的分组**：先去掉公共梯度分量再聚类，否则这个 variant 等于 uniform。
5. **改权重这条线**：我的建议是先放下。如果要再试，应该换问法——比如强制 teacher 先用读机制的工具给出可检验的定位，再允许编辑；并且监督整段后续轨迹而不是一步。按现在的证据，它的优先级低于 2 和 3。
6. prereg §8 末条（用 AD 的数据重做设置 B）：建议不做。

## 6. 名词表

- **θ₀**：K 条轨迹上做轨迹 SFT 得到的学生（seed 0），是 v0 和 P1 设置 A 的起点。
- **修复 episode**：一条学生失败轨迹经 teacher 最小修改后，在真实环境里验证成功的完整轨迹。
- **决策行**：一条训练样本，输入是历史 h_t，监督目标是 y_t。
- **G1 / G2 / G3 / G5**：换位置 / 换目标 / 出错状态 / 组合改动四类合成题生成器。
- **R / G / S / D 桶**：第一批修复 / 扩题得到的修复和学生成功 / 学生在合成题上自己的成功 / K 条原示范。
- **D-data、uniform、D-param、Dparam-full**：v0 的四个训练臂，见 §2.7 的表。
- **配对（s, a_f, a_r）**：失败轨迹和修复轨迹第一个分叉处的状态、学生的动作、修复的动作。
- **E0–E5 / B0–B5**：P1 设置 A / B 的条件，见 §3.4、§3.5。
- **M1–M4**：P1 的四个评测指标，见 §3.4。
- **附带伤害**：学生原本做对的决策里，编辑后 greedy 动作被改变的比例。
