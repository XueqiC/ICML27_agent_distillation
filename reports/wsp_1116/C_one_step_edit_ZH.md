# C 组：不用优化器，一步写出改动

状态：定稿（11-16 13:50 CST）。只做了 C1（一步梯度改写）及其按回复成分的拆分；C2、C2b、C4、C5 没做，见 §6。

## 1. 要回答的问题

预注册 Q2：**一个有效的改动，能不能不靠优化器迭代、从可读的信号直接写出来？** C1 取最直接的可读信号：SFT 目标在原始模型处的梯度。它就是"SFT 的第一步"，只是步长由我们直接指定，并且只走这一步。如果这一步能拿到 SFT 增益的一大部分，说明可读信号里信息足够，值得让 teacher 去写；如果不能，说明 SFT 的效果来自多步之间的相互修正，不是一个方向。

## 2. 名词

- **训练目标 L**：和轨迹 SFT 完全相同。对 K20 的每个决策步 t，L = teacher 回复 y_t 的全部 token 的负对数似然（每条轨迹先对 token 取平均，再对轨迹取平均）。
- **G_m**：L 对第 m 个模块完整权重矩阵的梯度，在原始模型处算一次。258 个模块，每个一个矩阵。
- **一步改写**：Δ_m = −η · [G_m 的最优秩 r 近似]，所有模块同一个 η。不挂 LoRA，不做任何优化器更新。
- **步长**：用 ‖Δ‖_F（258 个模块合计）来报告，而不是 η。参照：SFT 学生的 ‖Δ‖_F 是 5.9（K20）。
- **训练题整题成功率（T2-train）**：K20 的 20 个训练题，从初始状态让模型自己做到底（greedy，最多 40 步）。它和 teacher-forcing 的区别是：模型每一步看到的是它自己前面的输出，不是 teacher 的。
- **回复的两部分**：每个回复是 `Thought: …` 一行加 `Action: …` 一行。K20 的 8,552 个监督 token 里，Thought 部分 5,859 个，Action 部分 2,693 个。

## 3. 怎么做的

1. **算梯度**（hpg B200 和 LONI A100 各算一次，结果一致）：逐条轨迹反传，float32 累加，得到 258 个 G_m。
2. **截秩**：每个 G_m 留前 1 / 4 / 16 / 64 个方向。
3. **选步长，第一版（预注册 §10）**：在一组 ‖Δ‖_F 上算训练目标 L，取 L 最小的。
4. **评测**：dev140。
5. **第一版失败后改了选法（预注册 §14，先登记后跑）**：步长改由训练题整题成功率来选，hpg 和 LONI 各跑一遍 20 题，合起来 40 次。
6. **按回复成分拆开（预注册 §15，我加的）**：分别只用 Action 部分、只用 Thought 部分的 token 算梯度，各做一步改写；并把 L 拆成两部分分别报告。

全程没有调用 teacher，没有用 dev140 做任何选择。

## 4. 结果

### 4.1 梯度本身是低秩的，训练 loss 也确实能一步降一半

- 梯度的范数集中在少数方向：每个模块的第 1 个方向占 ‖G‖² 的 70%，前 4 个 87%，前 16 个 95%。
- 训练目标（K20，teacher-forcing）：

| ‖Δ‖_F | 0（原始） | 0.125 | 0.25 | 0.5 | 1 | 2 | SFT（5.9） |
|---|---|---|---|---|---|---|---|
| L，秩 64 | 1.03 | 0.48 | 0.53 | 0.73 | 1.07 | 1.74 | 0.0000 |
| L，秩 1 | 1.03 | 0.49 | 0.53 | 0.70 | 1.03 | 1.78 | |

- 很小的一步（范数是 SFT 改动的 2%–4%）就把训练 loss 从 1.03 降到 0.48–0.53，秩 1 和秩 64 几乎一样。再大就反弹。K100 上是同样的形状（原始 0.95，最低 0.48）。
- 但"整步完全匹配率"（teacher-forcing 下一步里所有监督 token 都对）只从 7.6% 到 9%–10%；SFT 是 100%。

### 4.2 按训练 loss 选出来的那一步，把模型改坏了

| | dev140 |
|---|---|
| 原始模型 | 40–44 题（29%–31%） |
| 一步改写，‖Δ‖_F = 0.25（训练 loss 第一版网格的最低点），秩 64 | 8%（11）（hpg）、7%（10）（LONI） |
| 同上，秩 16 / 4 / 1 | 7%（10） / 7%（10）（hpg）、6%（8）（LONI） / 6%（8）（两边都是） |
| 一步改写，‖Δ‖_F = 0.125（细网格的最低点），秩 64 | 18%（25）（LONI） |
| SFT 参照 | 81–93 题 |
| SFT 参照训到第 10 次更新 | 27%（38）（hpg）、26%（37）（LONI） |
| SFT 参照训到第 40 次更新 | 54%（75）（hpg）、59%（82）（LONI） |

- 训练 loss 降了一半的改动，dev140 从约 42 题掉到 8–11 题。
- 看轨迹，原因很具体：‖Δ‖_F = 0.25 时，模型 77% 的回复变成了字面的 `Thought: ...`（三个点）。这是 system prompt 里格式说明行的占位写法，teacher 的 315 个回复里一次都没有出现。回复平均长度从 116 个字符降到 44 个，重复动作从 27% 升到 44%。

### 4.3 改用训练题整题成功率来选步长：没有一档高于原始模型

20 个训练题，hpg 和 LONI 各一遍，合计 40 次。

| | 做对的比例（40 次） |
|---|---|
| 原始模型 | 50% |
| SFT（seed 0） | 100% |
| 一步改写，秩 64，‖Δ‖_F = 0.031 / 0.062 / 0.125 / 0.188 / 0.25 / 0.375 | 42% / 38% / 45% / 18% / 15% / 5% |
| 一步改写，秩 1，‖Δ‖_F = 0.062 / 0.125 / 0.25 / 0.375 | 32% / 30% / 8% / 2% |

- 小步长不伤模型，但也不帮忙（38%–45%，原始 50%）；大步长把模型改坏。**没有可用的步长。** 按 §14 预先写下的规则，C1 记为"没有找到可用的改写"。

行为随步长的变化（hpg 的 20 题）：

| | 字面 `Thought: ...` 的回复占比 | 重复动作 | look / help / inventory | 回复平均字符数 |
|---|---|---|---|---|
| 原始 | 0% | 29% | 30% | 113 |
| SFT | 0% | 7% | 2% | 90 |
| ‖Δ‖_F = 0.031 | 0% | 36% | 38% | 82 |
| 0.062 | 0% | 33% | 33% | 64 |
| 0.125 | 0% | 42% | 10% | 62 |
| 0.25 | 77% | 55% | 0% | 44 |
| 0.375 | 84% | 56% | 0% | 43 |

- 随步长变大，最先变的是回复长度（越来越短）；look / help / inventory 在 0.125 才降下来；到 0.25 Thought 塌成占位符。重复动作一直在变多，从来没有变少。

**一个真实的例子**（训练题：把两个 statue 放到 coffeetable 1 上；每个条件的前三个回复）：

| 条件 | 前三个回复 | 结果 |
|---|---|---|
| 原始 | `Thought: The goal is to find two statues and place them on coffeetable 1. I should start by looking around…` → `look`；然后 `inventory`；然后 `go to armchair 1` | 40 步用完 |
| SFT | `Thought: I’ll search the nearby surfaces for the statues.` → `go to coffeetable 1`；`go to diningtable 1`；`take statue 1 from diningtable 1` | 9 步做完 |
| 一步改写 0.062 | `Thought: I need to find two statues. I'll start by looking around the room.` → `look`；`go to sofa 1`；`go to armchair 1` | 40 步用完 |
| 一步改写 0.125 | `Thought: I'll check the armchair 3.` → `go to armchair 3`；`go to armchair 2`；`go to armchair 1` | 17 步做完（其中 5 个动作不可执行） |
| 一步改写 0.25 | `Thought: ...` → `go to armchair 1`；`go to armchair 2`；`go to armchair 3` | 40 步用完 |

这一题上 0.125 那一档做对了，但 40 次里它总共只做对 18 次，和原始模型的 20 次没有差别。从这个例子能看到的是：一步改写先学到的是 teacher 的"话少"，而 SFT 学到的"先去哪里找"（直接去 coffeetable、diningtable）没有出现。

### 4.4 为什么：训练 loss 的 97% 在 Thought 上

原始模型在 K20 上（teacher-forcing）：

| | token 数 | 每个 token 的平均 loss | token 准确率 | 占总 loss |
|---|---|---|---|---|
| Thought 部分 | 5,859 | 1.185 | 75% | 96.7% |
| Action 部分 | 2,693 | 0.089 | 99% | 3.3% |

- 给定 teacher 的 Thought，原始模型在 90.5% 的步里已经能把 Action 部分完全写对。也就是说，在 teacher-forcing 下动作几乎不需要学；loss 几乎全是"Thought 的措辞和 teacher 不一样"。
- 所以全量梯度指向的是"把 Thought 写得像 teacher"。一步之后 Thought 变短、再大就塌成占位符；而决定成败的"下一步去哪"在这个梯度里只占 3%。
- **只用 Action 部分的梯度**（LONI，20 题）：‖Δ‖_F = 0.031 / 0.062 / 0.125 时做对 30% / 45% / 30%（原始 50%），也没有超过原始模型。更大的步长因作业超时没有跑完，没有重投。
- 只用 Thought 部分的梯度，数值上和全量梯度一样（符合上面的占比）。

这解释了"teacher-forcing 的 loss 降一半、闭环成功率不升反降"：teacher-forcing 下模型每一步都拿着 teacher 写好的 Thought 和历史，动作本来就对；闭环里它要靠自己的 Thought 和自己走出来的历史，而这一步没有改善这个。

## 5. 结论

1. **一步梯度改写不能替代 SFT，也不能替代 SFT 的一小部分。** 最好的一档在训练题上是 45%（原始 50%，SFT 100%），dev140 最好 18%（25）（原始约 42 题）。预注册 §5 的判据（秩 ≤ 4 的改写 dev140 ≥ 59）没有达到，而且差得很远。
2. **SFT 的效果不在第一步的方向上。** SFT 自己训到第 10 次更新也只有 37–38 题，到第 40 次更新才到 75–82 题。
3. **teacher-forcing 的训练 loss 不能用来选改动。** 它 97% 衡量的是 Thought 的措辞。任何"不迭代"的写法如果用它当目标或当验收，都会被引到文风上去。验收必须用闭环 rollout。
4. 梯度是低秩的（第 1 个方向占 70%）并没有帮上忙：低秩的那个方向正是"文风"方向。

对 WSP 的含义：最直接的可读信号（一次梯度）里，关于决策的信息不到 3%，而且被文风信号盖住。要写出有用的改动，得先把"该改的是什么"从 Thought 的措辞里分离出来：只对动作 token、并且在模型自己的历史上（而不是 teacher 的历史上）取信号。后者这一轮没做。
