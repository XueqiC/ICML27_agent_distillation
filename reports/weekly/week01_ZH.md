## 0. 本周要点

1. **方向更新**：研究对象从"多少经验够用"改为 **Drop-In Agent Distillation**。目标是从少量可信样本出发，蒸馏一个能在**原 harness H0 不变**的条件下替换教师、独立完成任务的小模型。
2. **普通 SFT 比预想的强得多**：剂量够时（约 40 万监督 token），K=20 平均 107.7/140，K=50 平均 114.7/140，追平教师的 114。官方 baseline（Kang、AgentGym、LEAP）全部低于同 K 的 Seed-SFT。它们的失败里混入了大量剂量不足和"只在种子任务上采集"的问题。
3. **只在种子关联实例上交互，学不到新信号**：学生对种子拟合 94–98%。在剂量充足的学生上，LEAP 拿到 0 条纠错，ETO 只找到 3 对。
4. **新发现（P1 预分析）：平均分持平不等于能直接替换。** K=50 学生与教师的总分相同，但逐题看，教师会做而学生不会的有 9–13 题，学生会做而教师不会的有 10–15 题（见 §3.4）。这正是新方向要研究的现象；但还要先测教师自己重跑一次的不一致程度，才能下结论。
5. 下周优先级：P0 固定口径 → P1 用已有检查点做诊断表 → P2 同状态交叉续跑，并在 K=5 上做公平的扩展基线。

## 1. 研究问题

### 1.1 实践问题与设定
已有一个能工作的大模型 Agent：教师 T 在 harness H0 里完成某类工作。H0 包括上下文组织、工具接口、状态记录、重试与终止规则。我们想把 T 换成小模型 S，降低重复执行的成本，同时保留整个系统。

- **目标量**：J(S, H0)，即 S 接入不变的 H0 后独立执行的任务成功率，或预先定义的效用。部署时教师和训练辅助全部退出。
- **K** 是初始可信样本数（环境验证过的教师轨迹），**不是**可访问的任务数。之后可以开放新实例、调用教师、做真实交互；新增的教师监督、环境交互和训练曝光**分别报告**。
- 本项目中：S = google/gemma-4-12B-it @707f0a3b，T = gpt-6-luna（黑盒，只用采样输出）。H0 = ALFWorld 的 ReAct harness（见 §5.0）。

### 1.2 三个必须分开测的量
1. **输出拟合**：在独立的固定历史上，教师响应的似然或监督损失。
2. **局部决策质量**：给定同样合法的历史，学生能否产生可执行、对任务有用的动作。允许多条正确路径，不能用"和教师字符串一样"来代替。
3. **自主执行**：学生从头开始在 H0 里一直行动到终止，最终的结果。

第一性原理：如果学生在每个相关历史上，都能产生和教师相同、会影响后续执行的完整输出分布，两套系统的轨迹分布就相同，不存在神秘的"接入后能力消失"。问题只可能来自近似蒸馏在某些地方没有保留影响任务的行为。

### 1.3 三层问题
- **现象**：训练充分以后，局部决策质量与完整执行效果之间是否仍有稳定的不一致？平均分持平时，逐题替换是否可靠？
- **原因**：哪些错误会在 H0 的反馈与控制中被纠正，哪些会持续传播？few-shot 是否让某些关键行为更难学到？
- **方法**：怎样构造和利用蒸馏监督，让学生在原输入、原工具、原流程下学会这些行为？

### 1.4 首要机制假设与必须对照的解释
**主假设 H1**：学生学会了正常路线，但没有学稳"偏离之后利用 H0 反馈继续完成任务"。一个小错发生后，环境返回了新信息，学生却没有据此更新判断，小错因此一路传播下去。

必须正面对照的其他解释（可以同时存在，干预的救回比例不能相加）：

| 候选原因 | 支持它的证据 | 反证或替代解释 |
|---|---|---|
| 基本知识/技能缺失 | 简洁且信息充分的局部问题也答错；补普通新任务就改善 | 局部能力已经好了，只在原上下文或自主历史中出错 |
| 原上下文中的信息用不好 | 同样的事实只改呈现方式，决策就变好；教师受影响小得多 | 改写其实增加了事实、子目标或建议 |
| 学生状态覆盖不足 | 教师历史上做得好，学生自己走出来的历史上做得差；普通学生状态监督能消除差距 | 覆盖了相同历史以后仍有系统性差距 |
| 小错之后恢复不了（H1） | 同一个错误，教师续跑能恢复，学生续跑不能；对反馈或状态处理做干预能改变这种关系 | 初始错误本身就不可恢复，或者只是通用能力差 |
| 协议/实现错误 | 只修序列化、解析或截断就恢复 | 这首先是工程问题，不作为核心机制 |

### 2.2 定位
- **已经被做过的**："固定 harness 下蒸馏"（HAD）、"学生状态上的逐步教师监督"（SOPD、DAgger）、"关键错误处的恢复监督"（PivotOPD）、"纠正后用学生续跑验证"（FutureBridge）、"改 harness 来适配小模型"（Better Harnesses）。
- **我们可能的空间**有三层：
  1. **黑盒 API 教师，从少量可信样本起步**。上面多数方法要么用开源教师（HAD、FutureBridge、PivotOPD 的 KL 参照），要么需要教师 logits。
  2. **先把现象打实**：在剂量和覆盖都控制好以后，"平均分持平但逐题不等价"是否稳定存在，错误在 H0 里怎样传播。前人都把蒸馏后的差距直接当作方法的出发点，没有排除剂量和覆盖。
  3. **用真实执行分支来定义监督的正确性**（多解、按后续影响加权），并通过诊断预测哪类监督有用。
- **必须正面比较的对象**：HAD（适配版）、SOPD 或黑盒 DAgger（重新实现）、PivotOPD 式的恢复监督（若时间允许，做适配版）、Grounded Augmented-SFT，以及剂量充足的 Seed-SFT。
- **与现行 baseline 规则的冲突**：HAD、SOPD、SmartAD、PivotOPD 都**没有完整的官方代码**，FutureBridge 需要 logits。按最初定下的 baseline 规则，它们都不能以"官方复现"的名义入表，只能标注为"适配版或重新实现"进入比较。这需要你确认（§8）。

### 3.3 已有发现（对新方向的含义）

| 已有观察 | 可以支持的判断 | 不能推出的判断 |
|---|---|---|
| 3–6 万 token 处有一个与 K 无关的低谷，剂量补足后恢复 | 优化是实质性的混杂因素；官方配方在小数据下大概率剂量不足 | 低谷由 harness 不兼容造成；这个阈值具有普遍性 |
| K20 107.7、K50 114.7，教师 114 | 在这个分布上，学生接入原 harness 有可能达到教师的平均水平 | 普遍存在不可跨越的障碍；K50 已经逐题替换了教师 |
| 种子拟合 94–98%；LEAP 对照 0 条纠错，ETO 对照 3 对 | 当前采集分布已经很难提供新的纠错信号 | 交互学习本身无效 |
| 增益主要来自加热/冷却这些 base 不会、种子又覆盖到的类型 | 知识/技能覆盖解释了一部分收益 | 所有剩余失败都是"会但不会用反馈" |
| k2s1 和 k2s2 覆盖的类型相同，结果是 86 对 59 | 粗粒度类型解释不了全部差异 | 原因一定是恢复分支或 harness 信息 |
| 机制分析：M1a=0；K 小时 I4（给动作）比 I3（给建议）更有效 | 局部知识与自主执行可能不一致；从信息到动作的转换值得检查 | I4/I3 的差异唯一指向某一种机制 |
| AgentEvol 起点差时越训越差（k5s2 44→12、k10s1 64→10），K50 时稳步上升（93→102） | 用学生自己的成功轨迹反复训练，会放大起点上的缺陷 | — |

### 3.4 新的预分析（P1 的第一张表，今天用已有评测算出）

| 检查点 | 学生成功 | 两者都成功 | **只有教师成功** | **只有学生成功** | 都失败 |
|---|---|---|---|---|---|
| base | 62 | 61 | 53 | 1 | 25 |
| K5 s0 / s1 / s2（40 万 token） | 72 / 101 / 81 | 70 / 90 / 76 | 44 / 24 / 38 | 2 / 11 / 5 | 24 / 15 / 21 |
| K20 s0 / s1（p40） | 115 / 110 | 103 / 99 | 11 / 15 | 12 / 11 | 14 / 15 |
| K50 s0 / s1 / s2 | 112 / 116 / 116 | 102 / 105 / 101 | 12 / 9 / 13 | 10 / 11 / 15 | 16 / 15 / 11 |
| K100 s0 / s1 / s2 | 115 / 106 / 112 | 105 / 97 / 104 | 9 / 17 / 10 | 10 / 9 / 8 | 16 / 17 / 18 |

解读：
- K≥20 时，学生和教师的总分持平，但**每个方向都有约 10 题不一致**。按逐题看，"直接替换"并不等价。
- 问题在于：教师是随机采样的 API，它自己重跑一次也会翻转一些题，而我们只跑过一次教师。**下一步先重跑一次教师**（约 2,900 次调用），测出教师自己和自己的不一致。
  - 如果学生和教师的不一致明显超过教师和教师的不一致，说明存在系统性的替换缺口，这就是新方向的现象。
  - 如果两者相当，就说明在 valid_seen 上 K≥50 的替换已经达到噪声水平，现象要到更难的分布或第二个工作流里去找。

| **P2** | 同状态交叉续跑 | 在相同快照上测 R_TT、R_ST、R_TS、R_SS，区分"当前这一步的问题"和"之后恢复的问题" | 2–3 天；每个学生约 1.6k 次教师调用 |
| **P2** | 补强扩展基线（K5 × 3 个种子集，所有方法有相同的新实例访问权） | Seed-SFT、Grounded Augmented-SFT、开放新实例的学生状态监督（黑盒 DAgger/SOPD）、HAD、方法原型 | 约 1 周；每格约 1–2 GPU 小时，教师约每格 45 条轨迹 |
| **P3** | 闭环分支蒸馏原型 | 检验针对已定位机制的监督是否有额外价值，并区分数据带来的收益和训练目标带来的收益 | P2 之后 |
| **P4** | 第二个工作流 | 同一机制和方法是否在 ALFWorld 之外成立 | 准备工作与 P2 并行（选择环境、移植 harness） |
| 收尾 | ETO、IPR、LEAP K50/K100 | 作为"只在种子关联实例上"这一旧设定的结果保留 | 已经在跑：ETO 今晚到明早，LEAP 明天，IPR 周五到周六 |

**第一轮必须给出明确决策**（§6）：
- 如果扩展 SFT 就消除了差距，说明主要是覆盖问题；
- 如果学生状态监督就能解决，说明主要是已知的分布偏移；
- 如果 HAD 已经解决，在 few-shot 下复现它不足以支撑顶级贡献；
- 只有在强基线之后仍然存在**可以定位、可以干预、能预测训练收益**的失败过程，才围绕它定型方法。

## 5. 实验设计

### 5.0 P0：口径与 H0
- **H0（ALFWorld）组件清单**：
  - system prompt + 任务描述 + 每步的观察 JSON（含 admissible commands）；
  - 完整历史放在上下文里，不做记忆压缩；
  - 输出格式不合法时，返回解析器的反馈轮；
  - 每局 40 步，每步最多 1,024 token，关 thinking，贪心解码；
  - 成功或步数用完时终止；上下文超过 32k 记为 `context_overflow` 终止。
  这些写成 `harness_manifest.json`，任何对照都只改其中被干预的字段。
- **报告口径**：K（初始可信样本）、独立实例数、任务类型数、新增教师调用和 token、环境步数、训练曝光（token 和遍数），六项分开列出。
- **划分**：
  - dev140 已经用得很多，继续作为开发证据，不改称测试集；
  - valid_unseen（134 局）作为**最终封存评测**，诊断、调参、生成训练数据都不碰它；
  - 新开一个 `train-holdout` 开发池：从 ALFWorld train 里留出的、不参与种子和扩展的实例，用于方法开发和选择检查点。
- **检查点**：K5 / K20 / K50 × s0–s2，都取约 40 万 token 的足剂量版本（已有），再加 2–3 个低谷检查点（例如 3 遍和 5 遍），用来看剂量效应。

### 5.1 A：诊断表（P1）
所有模型使用**同一个固定的历史库 Hb**，不能给每个模型一套难度不同的历史再比较。
1. **输出拟合**：从教师的 dev140 轨迹（共 2,862 步）里按类型和步序分层抽 500 步，计算每个检查点对教师整步回复的逐 token NLL。
2. **局部决策质量**：Hb = 上面 500 个教师历史，加上 base、K5、K20、K50 学生实际走出的合法历史各 100 个（按"后来成功/失败"分层），所有模型共用这一个库。在每个历史 h 上取模型的贪心下一步 a，打两种标签：
   - (i) **可执行**：a 能解析，而且在 admissible 列表里；
   - (ii) **有用**：用确定性前缀重放到 h，执行 a，然后让教师接手（2 个样本）。如果教师能在剩余步数内成功，而且所需步数没有比教师自己走这一步多 1 步以上，就记为有用。
   便宜的近似指标：a 是否落在教师在 h 上的 4 个采样动作之中。先在一个子集上和标签 (ii) 对照，验证这个近似指标可靠，再大规模使用。
3. **自主执行**：dev140 成功率（已有），加上 §3.4 的配对成功集合。**另外重跑一次教师**，估计教师自身的不一致。
4. **首次实质偏离**：沿学生失败局逐步做教师接手，第一个"接手后成功率明显下降，或所需步数上升 2 步以上"的 t，记为首次偏离。现有 FCE 只每 4 步探一次，P1 要在 gap 局里补上密集探测。
5. **干预后的持续性**：复用 K20 s0（24 局）和 K5 s0（43 局）已有的 I3/I4 续跑轨迹，统计学生被修正一次以后，到下一次停滞（或失败）之间还能独立推进多少步。

### 5.2 B：同状态交叉续跑（P2）
- **快照**：ALFWorld 用确定性前缀重放（analysis/mechanism/branch.py 已经实现，会校验环境状态和可见历史是否一致）。H0 的状态是完整历史、步数计数和剩余步数。不能复现的快照不用。
- **快照从哪里取**：
  - (a) gap 局的 t\*（已有）；
  - (b) §5.1 找到的首次偏离点；
  - (c) 对照组：在双方都成功的局、只有学生成功的局里随机取的状态，避免只看失败。
  每个学生取约 40 个快照。
- **候选下一步**：教师采样一次整步输出（Thought + Action，原样写进历史，各臂共用这一份）；学生取它在该快照上实际给出的那一步。
- **续跑**：教师 2 个样本；学生用贪心加 4 个 T=0.7 的样本（与 I 系列干预一致）。成功与否按剩余步数判断。
- **估计量**：
  - Δ_T = R_TT − R_ST（教师续跑时，换成学生这一步造成的损失）；
  - Δ_S = R_TS − R_SS（学生续跑时，同样的替换造成的损失）；
  - 交互量 = Δ_S − Δ_T。
  按任务做聚类 bootstrap 估置信区间，正值和负值都保留。这个交互量是"这组干预下"的量，不是整个任务差距的可加分解。
- **零成本起点**：现有数据已经给出 t\* 处的三格：
  - R_TT(t\*) 就是 FCE 在 t\* 的接手；
  - R_TS(t\*) 就是 I4；
  - R_SS(t\*) 就是 I0；
  - R_ST 需要从 t\*+1 接手，在做过密集探测的局里已经有了。
  P1 里先把这张初步 2×2 拼出来。
- **之后接 harness 干预**：只对 H0 里真实存在的组件做（ALFWorld 的 H0 没有记忆压缩，也没有循环提示）。例如"上一步无效"的反馈在原文里是 "Nothing happens."，可以检查学生是否对这个反馈有反应。凡是会改变决策含义的反馈分支，都必须用真实执行产生，不能只改观察文本。

### 5.3 C：同信息的输入对照（P2，诊断用）
- 在相同状态下比较原生输入和"只做格式整理"的输入。整理只能用可见历史里已有的事实，例如已经去过的容器及看到的东西、背包里的物品、上一步的结果，确定性地汇总后放在当前步。不得补充隐藏事实、正确动作或规划。
- 教师和学生都做这组对照。如果有改善，只说明信息呈现会影响决策；要支持更窄的机制，还得结合具体字段、反馈事件和跨模型对照。它不作为"H0 不变"的主结果。

### 5.4 D：公平的扩展基线（P2，K5 × s0–s2）
- **相同的访问权限**：从 ALFWorld train 里抽一个共同的新实例池 P_new，排除种子实例、dev/test 和 train-holdout，按类型分层，每个种子集 N=45 个。**所有方法使用同一份 P_new**。K5 + 45 = 50，可以直接对照 K50 Seed-SFT（114.7）：检验"少量可信样本 + 扩展"能否追上"更多可信样本"。
- **方法臂**：
  1. 足剂量 Seed-SFT（只用 K）——已有；
  2. **Grounded Augmented-SFT**：教师解 P_new 里的实例（每个最多 3 次），经环境验证的成功轨迹并入训练；
  3. **开放新实例的学生状态监督**：学生（以 Seed-SFT 为起点）在 P_new 上 rollout，教师在学生走到的状态上给出下一步（黑盒采样），聚合以后再做 SFT（黑盒 DAgger；SOPD 视代码与接口情况作为适配版，见 §2）；
  4. **HAD**（固定 H0 的适配版，视代码情况，见 §2）；
  5. SmartAD（若有可用代码）；
  6. 方法原型（P3）。
- **剂量**：以 40 万 token 为起点，但对新数据配方各加一个 20 万和 80 万 token 的剂量检查，不把 40 万当成定律。教师 token、环境步数、轨迹数、训练 token 分开报告。
- **指标**：§1.2 的三个量，加上与教师的配对成功集合。

### 5.5 方法原型：闭环分支蒸馏（P3）
1. **找训练位置**：学生在 train 实例上按部署方式执行，找出真实的工具失败、前提遗漏、重复无效动作和决策分歧；正常成功的位置也保留。
2. **构建分支**：在可重放的状态上，由教师和学生各提出候选，实际执行，记录真实反馈，再由学生续跑。必要时也让教师续跑，用来区分"目标本身有问题"和"学生暂时不会后续步骤"。
3. **目标**：对历史 x 和经过验证的完整回复集合 Y⁺(x)，用

   L = −E_x[ w(x) · log Σ_{y∈Y⁺(x)} p_θ(y | x) ] + λ · L_anchor

   允许多解。w 由可复现的后续影响估计构造，并限制高方差权重；L_anchor 是正常成功路径上的 SFT，防止只学会修复而损害基本能力。学生概率来自学生自己，不需要教师 logits。
4. **部署**：只保留学生和 H0，不加任何提示或规划层。
5. **关键消融**：
   - 同样的分支数据，只做普通 SFT；
   - 同样的查询和交互预算，只做学生状态监督；
   - 同样 H0 下的 HAD；
   - 普通失败恢复数据和难度相近的数据；
   - 回报加权模仿；
   - 原型去掉执行验证、去掉成组反馈、去掉多解，各做一次。
   如果在同样的分支数据上普通 SFT 就能达到完整方法的效果，贡献就落在数据构造和机制上，不虚构一个必要的新损失。

### 5.6 第二个工作流（P4，选择标准）
要求：结果可验证；执行状态可以恢复（快照或确定性重放）；有能改变决策的真实工具反馈。候选：
- **AppWorld**：工具报错和副作用很丰富，数据库可以 save/load 加前缀重放；旧项目里有 adapter，需要移植到现在的 harness。
- **ScienceWorld**：测量和隐藏属性类任务较多，reset 可复现。
我倾向 AppWorld：它的反馈分支最贴近 H1，而且代码有起点。选它是为了检验机制，不是为了制造一个更大的差距。

## 6. 可能的结果与解读

| 实验 | 结果 | 解读与下一步 |
|---|---|---|
| A：教师重跑 | 学生-教师的不一致 ≈ 教师-教师的不一致 | valid_seen 上 K≥50 的替换已达到噪声水平；现象要到 K≤20、新实例分布或第二个工作流里找 |
| | 学生-教师的不一致明显更大，例如 >2 倍 | 存在系统性替换缺口：哪些题、在哪一步偏离，就是 P2 的对象 |
| A：三个量 | 局部质量已经接近教师，但自主执行仍差 | 支持"局部到执行的转化"这个现象，进入 B |
| | 局部质量本身就差 | 先承认蒸馏能力不足（覆盖或知识），优先看 D 里的扩展 SFT |
| B：2×2 | Δ_S > Δ_T，而且 R_ST 高：教师能从学生那一步恢复，学生不能 | 支持 H1（偏离后的恢复），在 K5 更明显时，few-shot 加剧这个问题的说法才有依据 |
| | R_ST 也低：学生那一步本身就不可恢复 | 主要是局部错误，不是恢复问题，监督应放在决策点本身 |
| | R_TS 低：给了教师那一步，学生仍然失败 | 通用的续跑能力弱，与具体偏离无关 |
| D：扩展基线 | Augmented-SFT（K5+45）≈ K50 Seed-SFT | K5 的缺口主要来自覆盖；在 valid_seen 上普通扩展已经足够，要接受这个结论 |
| | 学生状态监督明显好于 Augmented-SFT | 主要是已知的分布偏移；新方法必须超出这个机制才有意义 |
| | HAD 已经消除剩余差距 | 在 few-shot 下复现它不足以构成贡献，需要调整问题 |
| | 强基线之后仍有可定位、可干预的剩余错误 | 围绕它定型闭环分支蒸馏，再进入第二工作流、多训练 seed 和独立评测 |

**我的先验判断**（用来对照，不是结论）：在 valid_seen 上，K5 加 45 条扩展的 Augmented-SFT 很可能接近 K50 的水平，因为覆盖的作用很强。剩余的逐题不一致里有相当一部分是教师自己的噪声。因此，ALFWorld 未必能单独撑起"系统性替换缺口"这个现象；第二个工作流（反馈更丰富）很可能是关键，要尽早开始准备。

## 7. 风险
- **dev140 已经用得很多**：最终结论必须用 valid_unseen 和 train-holdout；dev140 上的结果只作为开发证据。
- **valid_seen 接近天花板**：K≥50 时教师和学生都在 115 左右，在这上面看平均差距没有区分力。重点放在逐题不一致和 K≤20 上。
- **算力**：hpg 的 mlperf 预留会占用 32 个 B200 节点，从 10-08 08:00 一直到 10-12。IPR（旧设定）在 4 卡上还要大约 2 天。P1 和 P2 主要消耗教师调用和单卡评测，受影响较小。
- **教师成本**：P1 加 P2 大约需要 1.5 万到 2.5 万次教师调用，加上 D 的轨迹采集。按批次给出预算，每批跑完再继续。

## 8. 需要你决定的事
1. **baseline 规则和新近邻怎么协调**：现行规则是"只跑代码完整的官方实现"，但 HAD、SOPD、SmartAD、PivotOPD 都没有完整代码，FutureBridge 需要教师 logits（§2.1）。我的建议：HAD 和 SOPD（或黑盒 DAgger）以"适配版"的身份进入主比较，并在表里单独标注；SmartAD 离我们的设定较远（QA/数学，每题需要多条正确样本），只在文中讨论。
2. **教师重跑 dev140 一次**（约 2,900 次调用）：用来估计教师自身的不一致，P1 的判断离不开它。
3. **IPR（旧设定）是否继续**：它在 4 卡上还要约 2 天。新文档的意见是收尾保留，我按这个继续，除非你想把 GPU 先让给 P2。
4. **第二个工作流**：AppWorld（我倾向这个）还是 ScienceWorld。
