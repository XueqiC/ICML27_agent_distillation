# A3：监督方式的 2×2（监督哪些步 × 监督回复的哪一部分）

状态：定稿（11-18 01:45 CST）。预注册 §18（A3），偏差记录 §20 第 6 条。

## 1. 要回答的问题

第一轮 C 组发现：SFT 的训练 loss 有 97% 落在 Thought 上，而决定一道题成败的是 Action。同时，teacher 做 WSP 时用的信号是"原始学生在 teacher 的历史上做错的那 90 步，只看动作"。于是有两个问题：

1. **只监督动作够不够？** 如果够，Thought 的监督是浪费的，WSP 只需要对准动作。
2. **只用做错的 90 步够不够？** 如果够，训练信号可以缩到三分之一。

## 2. 名词

- **步**：一条轨迹里 teacher 的一次回复，形如 `Thought: ... Action: ...`。K20 一共 315 步。
- **做错的 90 步**：把 teacher 的历史 `h_t` 喂给原始学生，学生给出的动作和 teacher 的动作 `a_t` 不同的那些步，共 90 步（文件 `turn_filter_k20_pairs90.json`）。
- **监督整个回复**：loss 计在 Thought 和 Action 的全部 token 上。
- **只监督 Action**：Thought 作为上下文给出，不计 loss；只有 `Action:` 那一行计 loss。
- **A0（参照）**：全部 315 步 × 整个回复，就是普通的 SFT。

## 3. 怎么做的

- 输入：K20 的 20 条轨迹。
- 做法：三次新训练，配方和 A0 完全相同（秩 16、α 32、lr 2e-4、全部 258 个模块、seed 0），只改"用哪些步"和"监督哪一部分"。每个 epoch 都是 10 次更新（按轨迹采样，20 条轨迹都在），训 32 个 epoch，**总更新 320 次，和 A0 相同**。
- 防错：旧的作业脚本会把这两个新选项悄悄丢掉。所以先跑准备阶段，确认监督 token 数对了才放行训练。

| 臂 | 用到的步数 | 每遍监督的 token 数 |
|---|---|---|
| 全部步 × 只 Action | 315 | 2,693 |
| 90 步 × 整个回复 | 90 | 2,483 |
| 90 步 × 只 Action | 90 | 764 |

- 输出：每臂一个 adapter，在 LONI 上评 dev140 两次、20 个训练题一次。

**一个真实的例子**（"做错的 90 步"里的第一个配对，题目 `pick_and_place_simple-Laptop-None-Ottoman-203` 的第 0 步，任务是把 laptop 放进 ottoman 1）：

```
h_t（上下文）:   房间的初始观察，可选动作里有 go to drawer 1 … go to ottoman 1、inventory、look 等
原始学生的回复:  Thought: The goal is to put a laptop in ottoman 1. First, I need to check if I have a laptop.
                 Action: inventory
teacher 的动作:  go to drawer 1
```

学生的动作（inventory）和 teacher 的动作（go to drawer 1）不同，所以这一步进入"90 步"。训练时这一步的监督目标是 teacher 在这一步的回复：
- 监督整个回复：teacher 的 Thought 和 `Action: go to drawer 1` 都计 loss。
- 只监督 Action：teacher 的 Thought 作为输入给出，只有 `Action: go to drawer 1` 这一行计 loss。

## 4. 结果

dev140 做对题数，每格评两次（LONI；原始模型 42 / 43）：

| | 监督整个回复 | 只监督 Action |
|---|---|---|
| 全部 315 步 | 89 / 90（64%）← A0 | 34 / 31（23%） |
| 只用做错的 90 步 | 76 / 76（54%） | 46 / 37（30%） |

20 个训练题（整题 rollout）：

| | 做对 | 进度分 |
|---|---|---|
| 原始模型 | 10 | 0.811 |
| 全部步 × 只 Action | 10 | 0.815 |
| 90 步 × 只 Action | 11 | |
| 90 步 × 整个回复 | 15 | 0.902 |
| K20 的 SFT（10 月训的那个，B4 表里的数） | 20 | |

## 5. 结论

1. **只监督动作学不出来。** 全部步只监督 Action 是 34 / 31，比不训练还低约 10 题；90 步只监督 Action 是 46 / 37，和不训练持平。预注册的判据是"和 A0 相差 10 题以内才算 Thought 的监督不必需"，实际相差 55 题以上。
2. **第一轮的猜测错了。** 我当时从"loss 的 97% 在 Thought 上"推出"真正要学的是动作"。这个实验说明反过来：学生是靠自己先写出的 Thought 带出动作的。只教它在 teacher 的 Thought 后面接动作，评测时它面对的是自己写的 Thought，学到的东西用不上。
3. **只用做错的 90 步、监督整个回复，保住大部分。** 76 / 76 对 89.5：增益 33.5 题，A0 的增益是 47 题，即三分之一的步拿到约 71% 的增益。
4. **对 WSP 的含义。** teacher 手术（P1 设置 B、第一轮 D 组）用的信号正是右下角那一格："90 个配对、只看动作"。这一格即使交给优化器走 320 步，也只有 37–46 题。所以那条路输的不只是"改权重的方式"，**监督信号本身就不够**。一个想取代 SFT 的方法，至少要用上整个回复的信息。

## 6. 没做的和局限

- 每臂一个 seed。"只监督 Action"两臂的两次评测相差 3 题和 9 题，但离 A0 差 40–55 题，结论不受影响。
- "只监督 Action"时 Thought 是 teacher 写的。没有试"Thought 用学生自己写的、只监督 Action"这种更接近评测分布的做法。
- 没有试中间情况（比如 Thought 的 loss 权重调低而不是去掉）。10 月做过的分段加权试验结论是权重不敏感，这里没有重复。
- 90 步是按原始学生的错误选的；没有对照"随机 90 步"。
